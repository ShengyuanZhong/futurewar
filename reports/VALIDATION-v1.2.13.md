## 关键首日边界

- 未到采购截止时可继续建墙；剩余白天到达实际去程与购用预算时，普通墙未齐也转赴店。已批准使命不会因施工状态变化往返。
- 未结算三次任务按最多三张预留；背包满时计入逐件 `drop`，批购一回合，逐张使用各一回合。下一帧实际库存/反馈作为依据，不增加虚拟动作或提前算成功。
- 实际封闭出口必须先 `remove`，下一观测才能穿过。驾驶到入口最后走一格已下车，之后按步行预算。
- 首日白天封门、首夜维修、满级维修和缺口待命均不能按返程预算提前召回工人；首日采矿不按回家路程筛矿点。
- R70 工人已在合法内侧且其他必须入内的工人已在内时才可就地封门；不会为封门提前回家，R71 不建墙。首夜真实受损墙仍修复、敌人离开占点后仍可肉身补位。
- 购物批准不代表墙已实建，不批准未完墙的另一工人提前侦察。若安全捣乱鬼已探明阵型并保持真实当前视野，可继续召唤；视野不足则不盲召唤，机器人自身不提供视野。
- 第二天及以后未进行本轮测试。返程策略的首日例外限定在 `day == 1 && is_day`，正常首夜防守和后续策略保留。

## 复现

从项目根目录运行：

```powershell
python CoreGeek/tools/validate_first_day.py --output reports/validation-v1.2.13.json
python CoreGeek/tools/smoke_worker_buyer_flow.py --output reports/http-worker-buyer-flow-v1.2.13.json
python CoreGeek/tools/smoke_worker_buyer_flow.py --unfinished --output reports/http-buyer-deadline-flow-v1.2.13.json
python CoreGeek/tools/smoke_first_day_flow.py --output reports/http-first-day-flow-v1.2.13.json
```

回归清单、源码及规则 SHA256 保存在 JSON。验证的是源码，未重新构建历史 wheel。预算避免己方低优先级施工或回防浪费购物窗口；持续敌方堵路、任务结算晚于可用窗口、金币不足或真实视野迟迟未取得，仍属于需要官方平台验证的边界，不能以本地成功替代官方完成率或胜率。
