# v1.2.12 首日采购工人与非对称商店

2026-10-12。用户确认地图、任务点与商店的路程并不对称，开拓者完成任务后再走向商店容易错过召唤窗口。本轮将首日BOSS采购和使用移交给非侦察工人，提前走向实际商店等待；开拓者继续2→1→2三次尝试，结束后直接回防。这里解决的是任务与购物串行的耗时，商店仍始终读取当局地图坐标，不能按基地镜像推算。

## 第一日分工

| 角色 | 白天任务 | 三次任务结束后 | 首夜 |
|---|---|---|---|
| 开拓者 | 任务二→任务一→任务二，沿用不预留购物/回防预算 | 立即走向原三炮共同操控位；不购买或使用BOSS券 | 三次已结束则操炮；未结束则沿用任务优先 |
| 侦察工人 | 实际可建墙完成后前往敌基地，沿用取车、两步驾驶与持续视野 | 保持侦察，给出真实炮位及当前炮手视野 | 已有BOSS时持续视野，夜间恢复步行 |
| 采购工人 | 与同伴先建三炮和墙；可出发后走向当局商店，等待三次任务实际结束 | 按真实成功数买0～3张并逐张使用，等待实际背包和反馈确认 | 结束采购、恢复原封门/缺口/首夜维护职责 |
| 捣乱鬼 | 保持既有安全侦察/破矿、缺口候补规则 | 可提供真实当前共享视野 | 保持原视野或缺口接替职责 |

`buyer_id` 固定采购工人的实际ID，优先采用既有留守/门/缺口工人的身份；侦察工人明确排除此ID。不会因两人位置变近或离店远近改变而互换任务，也不会把采购工人死亡时保留的背包转记给另一个角色。

## 建设条件与出发

新 `DayGate.dispatch_ready(ignore=())` 表示可派出工人，区别于 `day_ready()` 的实际封门可行性：必须已观测三炮和所有普通墙，门负责人保留封门石。白天受控入口可以开放，正在被实测敌方角色占据的预建墙位暂时忽略；普通空缺、已离开的占点角色和仅提交但尚未出现的墙不能视作建设完成。

采购工人的 `BossRaid.worker()` 放在普通 `DayGate/GapDefense/FirstNightDefense` 调度前。建设尚未就绪时返回False，继续原施工；就绪后购券使命优先，避免黄昏预算或维修采购把工人从商店拉走。若工人在完整17墙的内侧而入口已封，必须实际拆入口、下一帧确认开放后再走，不能用乐观拆墙结果穿墙。

侦察出发和当前视野准入使用同样的实际建设条件，不再因为采购工人位于远处商店、来不及返程而中断另一工人的视野。实际封门仍使用原 `day_ready/can_seal`，不把“可以出发”说成基地已经封闭。

已核实建设条件、采购工人真实离家后，记录一次出发批准。若原占点角色在白天离开，其空缺仍不算实建，但不会让已外派的采购工人往返补墙、侦察工人改去挖矿；先完成这次购券和视野使命，再恢复缺口补建/回防，避免新的路线折返。日志分别记录当前 `dispatch_ready` 与此前批准的 `construction_approved_round`。

两工人尚在家、被单格入口互挡时，复用实际协作让行：先让一人移到合法旁支，下一观测另一人才通过，不同时互换位置。已在敌方炮区提供视野的侦察工人仍受保护，不为通路临时挪走。

## 采购与库存

任务结束前只行走或在店旁等待，不提前购买/使用召唤券。任务三次真正结束且没有活跃phase后，按实际成功次数冻结数量；失败结束不算成功，金币余额不会额外增加配额。商店位置取 `Turn.zones` 的 `weaponShop`，从采购工人当前位置搜索合法邻格，不镜像NPC，也不使用开拓者的任务位置估算购物路程。

金币仍是队伍共享余额，物品进入购买角色自己的背包。`observe()`、`held_orders()`、`pending_buy/pending_use.actor_id`、库存增减与反馈都绑定采购工人；开拓者或侦察工人持有同名券不会增加已购数量。批购一次可以 `num=3`，但每张 `use` 各占一回合、选择不同合法出生点；召唤仍等待真实敌阵与当前共享视野，机器人不提供视野。

沿用当前价格、实际金币、背包容量、每日10次限制、失败重试、缺反馈防重复和首日日间部署窗口。已确认的数量不会因后来收入增加而变大，异常部分到账不会触发无限追加购买。中途新会话仅选择采购角色不能冒充已知采购历史。

背包容量不足时，每回合最多丢一份低价矿物腾位，等待实际背包更新后再购买；保留封门石和既有缺口补建石，不丢维修包或升级券。没有可腾空间的矿物时记录 `buyer_capacity_blocked`，不能发非法购买或假定腾位已成功。

## 返回与边界

采购/使用完成、零成功或白天部署窗口结束后，工人恢复原有门、缺口和首夜维修调度。封门必须在白天从合法内侧实际执行；若任务结算/采购太晚，真实路程可能导致无法入夜前封门，本轮不增加夜间建墙或虚构已回防的位置。

首夜若已离家采购的主工人尚未到达原恶意占点缺口，捣乱鬼可先进入实际空缺补位；主工真实回到邻格后再交还。原死亡接替规则保留，未外派的存活主工不被抢岗。本轮动作预约和其他角色目标保持优先，不能靠忽略真实占用或预测对方逃跑进入缺口。

与上版相同，采购预算只计算到店、buy和逐张use，不预留回防。这里的效率提升来自工人提前到店，不能保证任何地图、任务耗时或敌方卡位下都来得及部署全部BOSS。第二天后的经济、维护、角色复活和任务策略未在本轮改造。

## 开发入口

| 文件 / 函数 | 参数及作用 |
|---|---|
| `src/agent/boss_raid.py: select_buyer()` | 选择稳定的非侦察工人ID，写 `boss_raid.buyer_id`；死亡不偷偷改人 |
| `buyer_role(alive=False)` | 读取采购工人的实际Unit；False允许观测死亡后的保留背包，True供发动作前检查 |
| `dispatch_ready()` / `worker_mission_active(role)` | 当前真实施工条件、角色身份、第一日白天、配额和窗口判断 |
| `worker(role)` | 施工后提前赴店，等三次任务结束，再处理容量与采购/部署 |
| `approach_shop(role,post=None)` | 实际shop邻格、施工出口和工人协作路线；使用已有驾驶两段路径 |
| `free_capacity(role,needed)` | `needed`为需追加购买的数量；逐轮腾矿，不假定库存已变 |
| `observe/proposal/preparation/_deploy` | 承接原购券状态机，改为工人背包和工人反馈 |
| `pioneer(role)` | 旧接口兼容返回False；正式策略不再通过它采购 |
| `src/agent/brain.py: run/run_worker` | 三次结束后开拓者立即回防；工人采购使命优先于普通门/维修职责 |
| `src/agent/day_gate.py: dispatch_ready(ignore=())` | 只忽略当前实际被敌角色占据的墙格，不计采购工人的返程预算 |
| `src/agent/raid_scouts.py` | 候选、执行和视野准入均排除buyer，保留独立侦察者 |
| `src/agent/gap_defense.py: backup_needed()` | 主工死亡，或首夜已外派买者实际尚远时需要备位；以真实邻格位置交还 |

`first_day_policy` 增加 `buyer_id/buyer/dispatch_ready/buyer_departed/last_buyer_decision`。`buyer`记录位置、HP、持券数和实际指令；decision包含真实actor_id、当前金币/价格和等待原因。旧 `last_pioneer_decision` 字段作为解析兼容别名保留，其内容现在是采购工人的决策，应以buyer及actor_id识别执行者。
