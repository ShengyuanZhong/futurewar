# 工人避险、批量购券与夜间维修分工

更新至0.3.6，2026-09-21。避险沿用0.3.4，升级采用[集中升级与双维修](MAINTENANCE.md)。下面单维修工机制适用于升级未全部完成时，全部达标后切换双工人全天值守与轮流采购。修改类别为策略优化，涉及R02移动、R03工人/建造、R05机器人射程、R06购买数量与修复包。官方规则原件不变。

修改前的版本另存为[0.3.3源码快照](../../reports/baselines/v0.3.3-source.zip)及[SHA256清单](../../reports/baselines/v0.3.3-manifest.json)，此前0.3.2基准继续保留。

## 1. 工人避险

任务书规定机器人攻击距离为3格，采用切比雪夫距离。`worker_safety.robot_danger(turn)`在每轮根据实际存活机器人生成风险表：

| 与机器人距离d | 每个机器人的风险分 |
|---|---|
| 0–3 | `攻击力权重 × (5-d) × 10` |
| 4 | `攻击力权重`，作为一格警戒缓冲 |
| ≥5 | 0 |

攻击力权重为小型5、中型10、大型20、BOSS40，未知类型保守取40；多个机器人风险相加。这些数值是寻路惩罚，不是预测实际扣血。保守考虑所有观测存活机器人；眩晕剩余时间未知，仍保留警戒区，零血机器人忽略。不假设城墙阻挡机器人远程攻击。

`Strategy.route`只给工人传风险表，开拓者保持原有寻路。无风险时仍使用八方向BFS；有风险时使用Dijkstra，按`(累计风险, 实际步数)`排序。优先走零风险绕路，再比较距离；无法零风险时找累计风险较低的路径。地图障碍、角色当前占用和本轮预留仍禁止通行，不允许穿墙、互换或抢格。

工人处于警戒区时，先执行`evade_worker`：寻找离开警戒区的路线，只接受第一步风险不升高的移动；无法离开时尝试更低风险的邻格，再无路则等待，不继续原地采矿。低血且携带Medicine时仍沿用先用药的规则。

矿点筛选额外要求**采集站位与整条路径累计风险为0**，不能因高矿价进入危险区。普通夜间运矿也不会沿有风险的路线前往商人。没有安全矿点时，尝试回到安全可达的墙内通路；无路时等待下一轮重新评估。避险目标是减少暴露，不预测机器人下一轮准确移动/选敌，不能保证工人绝对不死。

## 2. 一次购买多张升级券

`Strategy.buy_upgrade(role)`按当前升级组购买对应的券，集中升炮时允许预购该炮下一等级的券，以响应中的`num`表达数量：

```text
本阶段缺券 = 未在本轮提交升级的目标数量
           -（存活角色已有券 + 本轮购买数量 - 本轮使用数量）
本次购买数 = min(本阶段缺券, 背包剩余容量, 可用金币 // 实时单价)
```

单价为0时只受需求和容量限制，不做除零。金币需扣除补炮预留及维修工尚缺修墙包的预算；同轮销售收入不提前计入。全队已有库存和本轮购买都参与统计，第二名工人不会重复买同一批券。

例如外围4面墙需要升2级，全队已有3张墙券，则一次买1张。火箭集中升级只先买当前一台需要的1张一级券，在库存已覆盖一级券后可预购1张二级券，两种券需要分回合购买，但可在同一次商店行程完成。

## 3. 第三天起的固定维修工

默认从第3天（第261回合白天、第331回合夜晚）开始，`WallGuard`选择一名存活工人：优先已有修复包最多者，同数按ID小者。选择写入`GameMemory.repair_worker_id`，库存或位置变化不会每轮换人。维修工死亡/从观测消失后，另一存活工人接替；若只剩一名工人，他负责维修，没有额外虚构采矿工。复活后不会强制把接替者换回去。新局沿用服务的会话重置机制。

白天维修工先补足**5个WallFixer**，允许一次买多个，受实际金币、背包空间、商店清单和补炮预算限制。已有3个时只补2个，不每次额外买5个。金币不足可部分购买；满包或资金不足时沿用卖矿/正常经济筹资，缺墙时保护石头。不自动丢弃或出售其他商店用品。

备足后恢复原白天工作；修复包为夜间值守保留，不因普通轻伤墙而提前消耗。接近黄昏时按到墙内通路的实际路径长度加`return_margin`召回；采购出发前也估算返程，赶不及时先回墙内。到场时间受动态占位影响，每轮重算。

同轮先安排开拓者，再安排维修工、最后采矿工。其他工人的升级券采购为尚缺的维修包留预算；已在本轮购入的维修包不重复预留金币。开局三火箭/采石/初始建墙阶段仍先执行，不为采购修复包跳过初始建设。

## 4. 墙内待命和30%触发

默认值守区域沿用设计图中的8格维修通路：相对基地左上角，上排`(0..2,1)`、下排`(0..2,-2)`，迎敌侧`(2,0),(2,-1)`；右侧基地按`dx→1-dx`镜像。过滤越界、非空地、预定墙格和炮位，实际路径还检查占用。自定义布局若不保留这些位置，可能无法完整值守，应同步调整`WallGuard.inner_cells()`。

维修工从外部安全返回；**已经进入通路后，巡护移动仅允许在通路内**。即使出现缺墙，也不为绕近路走到墙外。无待修墙时原地待命；若内侧存在更安全的位置，则沿内侧移动。没有修复包也继续值守，夜间不跑商店、不挖矿，次日补货。

触发条件使用整数比较：

```text
墙当前血量 × 100 < 墙最大血量 × repair_threshold_percent
```

| 墙等级 | 最大血量 | 默认触发维修 |
|---|---:|---|
| 1 | 1000 | 血量<300 |
| 2 | 1500 | 血量<450 |
| 3 | 2000 | 血量<600 |

恰好30%不消耗包。优先处理血量比例最低的可达墙，同值按迎敌方向和ID排序；相邻就发`use WallFixer`，否则沿墙内通路靠近。每轮最多一个维修动作，需要实际背包有包；已毁墙不能修，按既有白天补建逻辑处理。修复成功回血、库存扣除由平台下一轮观测确认；失败时继续依据实际血量/库存重试。

另一名工人沿用采矿、必要时交易、缺墙留石的任务，但增加避险。开拓者继续独占三炮夜间操作，维修工不占其P位置、不抢炮。未完成全部升级时，第1–2夜两工人均执行避险采矿。全部目标达到后立即双维修，不受第三天限制；后续全部可支出金币用于修复包，具体库存均衡、返岗交接和毁墙恢复见[维护策略](MAINTENANCE.md)。

## 5. 参数、模块与函数

新增配置均可省略，旧配置继续读取默认值：

| Settings字段 | 默认值 | 校验 / 含义 |
|---|---:|---|
| `repair_start_day` | 3 | 整数1–10，从该天白天开始选维修工、备货 |
| `repair_stock` | 5 | 整数1–100，升级完成前维修工目标库存；完成后按可用金币/容量分配 |
| `repair_threshold_percent` | 30 | 整数1–100，严格低于该百分比才夜修 |
| `return_margin`（已有） | 4 | 维修工黄昏返岗也使用的余量 |

`CoreGeek/config.example.json`已包含这些参数。配置启动时读取，改动后重启。

| 文件 / 入口 | 参数与返回 | 作用 |
|---|---|---|
| `worker_safety.py:robot_danger(turn)` | Turn→`dict[Pos,int]` | 本轮全图风险表 |
| `grid.py:Routes(turn,role,reserved=None,danger=None,allowed=None)` | 额外禁入集合、风险表、可通行区域集合 | 无风险BFS，有风险按风险/步数Dijkstra；allowed=None表示不限制区域，空集表示不能离开起点 |
| `Routes.cost/exposure/first` | 坐标→步数/累计风险/第一步 | cost仍为实际步数，风险路线可能比几何最短路更长；起点两种成本均为0 |
| `Strategy.route(role,allowed=None)` | Unit、可选区域→Routes | 工人带风险；缓存键包括预留格和allowed |
| `Strategy.evade_worker(role)` | Unit→bool | True表示已避险或因无路而停止经济动作 |
| `Strategy.mine/travel/clear_build_cell` | 沿用原参数 | 采矿站位和路径过滤风险；夜间运矿禁危险路线，工人让位不走向更危险格 |
| `Strategy.buy_upgrade(role)` | Unit→bool | 分阶段批量购券，全队库存与预算去重 |
| `wall_guard.py:WallGuard(strategy)` | 当前Strategy | 选择/维持维修工身份，无额外网络调用 |
| `WallGuard.inner_cells()` | →`set[Pos]` | 镜像后的墙内巡护区域 |
| `stock_missing()/budget_reserve()` | →int | 本轮仍缺修复包数与预留金额 |
| `daytime(role)` | Unit→bool | 采购、腾包、黄昏回岗；False交回普通白天流程 |
| `nighttime(role)` | Unit→None | 阈值维修、墙内移动或待命 |
| `GameMemory.repair_worker_id` | `int \| None` | 持久化维修工ID，由TurnService事务提交 |

日志新增`repair_worker`（本轮维修工ID或None）、`worker_danger_cells`（当前非零风险格数量）。HTTP路由、角色动作格式不变，购买仍为`buy`+`name`+整数`num`，维修为`use WallFixer`+`targetPos`。

## 6. 测试与边界

`tests/test_worker_safety.py`新增20项回归：多步安全绕行、采矿前撤离、危险矿回避、无路等待、死亡/眩晕机器人处理、批量采购三重限制、全队去重、第三天备货、预算预留、两侧墙内维修、30%边界、黄昏回岗、墙内远端巡护、库存保留、角色接替、修复失败重试/幂等及次日补货。

旧完整升级配送测试按响应`num`反馈金币/库存，并预置夜修库存以单独检验升级阶段。三个验证“工人安全采矿、开拓者开火”的旧夹具把敌人移到工人警戒区外；危险区应撤离由新增反例验证。没有更改官方动作校验来放宽测试。

0.3.4原始结果见[0.3.4验证报告](../../reports/VALIDATION-v0.3.4.md)。本版没有实现完整机器人预测或解除所有角色互相卡位；通路被占、无安全路线、修复包耗尽、同轮多墙遭致命伤时仍有能力边界，真实效果需要平台回放确认。

0.3.6新增双维修与轮流采购验证见[当前报告](../../reports/VALIDATION-v0.3.6.md)。`stock_missing(worker=None)`可按指定工人查询；`full_time`标志、`final_daytime`、`final_stock_targets`和`repair_supplier_id`维护完成阶段。
