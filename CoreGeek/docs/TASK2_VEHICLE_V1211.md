# v1.2.11 首日任务2→任务1→任务2与侦查车辆

v1.2.12已将首日BOSS购券和使用移交另一工人，先锋三次后直接回防，当前分工见[采购工人](WORKER_BOSS_V1212.md)。下文保留v1.2.11任务与车辆规则。

2026-10-12。根据用户最新策略，首日优先尝试三次任务，取消任务准入的完整题目耗时、购物和回防预算。此前v1.2.10因预算关闭任务行程的策略已停用。默认三炮、17墙、维修升级、捣乱鬼安全侦查与BOSS目标优先级保持；新增任务2车辆的正式协议与侦查工人驾驶。

## 首日任务

`TASK_SEQUENCE=(2,1,2)`，实际尝试账本仍按 `(day,accept_round,x,y)` 区分，同一任务2第二次领取不会去重。成功、失败、超时都结束一次尝试；领取失败不计数，完成与成功分开统计，购券数量仍按三次结束后的真实成功次数冻结0～3张。

`Strategy.task()` 第一日只按实际可达路径、官方点位有效性和冷却执行。任务时限仍交给任务模块用于解题和判定超时，不能因为剩余时间不足完整时限拒绝领取，也不为购物或返回基地预留回合。工人和捣乱鬼的安全、建墙、夜前回防规则未改。

有冷却时可以先走到任务2邻格等待；官方 `isValid=True` 且 `coldDownRounds==0` 才发 `acceptTask`。冷却不会因为执行另一个任务自动清零，而是按官方30回合计时，行走和做任务覆盖其中一部分。点位缺失、不可领或路径被暂时占用时保留重试，不虚构成功或提前进入购券阶段。

首日即使进入夜晚，只要还没结束三次尝试，开拓者仍优先处理剩余任务；活跃题目不因回防截止而中断。三次结束后恢复既有夜间操炮流程。死亡、题目超时、判题结果和任务控制器终止机制仍有效；第二天后的任务准入策略不在本轮修改范围。

`BossRaid.shop_trip()` 不再要求找到操炮位或计算回程，实际采购预算仅为到商店路程、购买一回合及逐张使用回合；持券部署也不预留回防时间。召唤仍按原有白天窗口和真实侦察准入执行，不假设入夜后能补生成第一夜BOSS。任务延续到夜晚可能放弃第一夜的部署机会，这是用户指定的任务优先取舍。

## 车辆来源和驾驶

来源为 `32_docs/任务书.md` §4.6.4 和接口的 `isDriving`、`challengerVehicle/defenderVehicle`。任务2成功后，程序等待地图实际出现己方小车；不根据奖励金额或任务成功自行创建车辆。每队同时最多一辆，已有车不重复刷新；最后一个白天回合或夜间完成时，车辆顺延次晨。小车第一夜首回合消失。

工人仍在自家墙构造就绪后才离家侦查，家防/缺口工人不被调走。侦查工人在取车和直接走路之间比较真实路线：

```text
步行：路径步数
已驾驶：ceil(路径步数 / 2)
先取车：步行到车的轮数 + ceil(车到侦察岗位的路径步数 / 2)
```

只取实际出现、未被角色占用、未被其他任务预约且至少净节省2轮的己车。取车受阻连续两轮时取消该位置的绕行；车被别人占用、消失或取车不能节省时间时继续走向侦察岗位，不等车。

走入己方车格发普通一步 `move`，下一帧 `isDriving=True` 才使用两步。驾驶例：当前(10,10)，输入两个连续切比雪夫距离1的坐标：

```json
{"action":"move","targetPos":[{"x":11,"y":11},{"x":12,"y":12}]}
```

这是同一角色的一条指令；第一点到起点、第二点到第一点都须相邻，不能把距离2终点作为唯一坐标。两步均按真实障碍、另一角色占用、弹道避让和本轮预约检查，并同时预约两格。接近侦察岗位时仅剩一步则正常单步离车，车留在原位置。夜间即使收到旧的驾驶标志，也只发一步。

车位属于独立中立元素：白天己方角色可以进入己车格；敌车不能进入；双方车格都不能建造。驾驶不妨碍采矿、建造、交易、使用物品或做任务。机器人仍每回合一格，不因为新增车辆协议放宽。

## 模块与参数

| 文件 / 入口 | 参数及职责 |
|---|---|
| `src/agent/first_day_tasks.py: TASK_SEQUENCE` | 固定首日2→1→2；事件账本和真实成功计数不变 |
| `brain.py: task(role)` / `pioneer_should_defend(role)` | 首日三次任务优先、取消任务预算回防、跨黄昏继续执行 |
| `boss_raid.py: shop_trip(role,use_count=1,start=None)` | 仅预算去商店、buy和use；`start`预测模式仍与实际缓存隔离 |
| `protocol.py: Unit.is_driving` | 读取官方布尔 `isDriving`；缺失时False，不能以本地计划代替 |
| `Turn.vehicle_cells(own=True)` | 返回己方车辆坐标；False返回敌方车辆坐标 |
| `Turn.walkable(pos)` / `land(pos)` | 通行可允许己车；land仍只认空地，用于建造等合法性 |
| `grid.py: Routes.path(goals,limit=None)` | 从真实搜索父链返回路线，排除起点；limit限制返回步数 |
| `vehicle.py: move_targets(turn,role,route,goals)` | 普通/夜间一步，白天已驾驶最多两步；返回坐标元组 |
| `protocol.py: move_command(pos)` | 接受一个Pos或Pos序列，输出官方targetPos数组 |
| `actions.py: ActionPlan.add()` | 两段逐格校验和原子预约；失败不部分写入动作或预约 |
| `raid_scouts.py: travel_budget(role,goal,route)` | 返回 `(预计轮数,值得取的车位或None)`，只用真实车辆和路线 |
| `worker_coordinator.py: move_to(...,route=None)` | 可传入侦察专用路线；保持协作让行，按驾驶状态生成移动 |

`raid_survey.posts[worker_id]` 增加 `travel_rounds/vehicle/is_driving`；取车阶段状态为 `collecting_vehicle`。`first_day_policy.task_schedule` 显示 `budget_policy=task_first_no_return_reserve`，回程和尾程预算为0，官方 `timeout_rounds` 只作为任务信息。

## 官方文字差异与验证范围

- 接口§2.1的 `targetPos` 总表仍写“移动只传1个目标”，与任务书明确的小车两步及用户明确的“两坐标”指令冲突。本实现按后两者发驾驶两段坐标，不改官方原件。
- 任务书§4.5.4.6在第二格碰撞时同时写“第1格移动有效”和“停留在第2格”，文字自身矛盾。本实现不预测碰撞后落点，只发送两格均已确认可走的路线；收到后续真实 `pos/isDriving` 后重新规划。
- 测试中的车辆刷新、任务答案和移动反馈为合成输入；真实双队碰撞、车位刷新采样和速度收益需平台复测。所有本轮验证只覆盖第一天，详见[验证报告](../../reports/VALIDATION-v1.2.11.md)。
