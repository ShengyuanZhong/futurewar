# 双工人行程与施工效率修复

版本 v1.0.1，2026-10-08。在 v1.0 基准上修正工人的任务选择和协作，涉及移动、采矿、建造与交易。移动仍按八方向一步、观测占用及同轮目标预留校验；夜间避敌、第三天起维修岗位和现有升级阶段继续参与决策。

## 原因与修正

本次用户没有提供新的完整报文；以下原因从源码及独立合成场景复现，不能把场景结果当成真实比赛的完整回放。

| 旧版原因 | v1.0.1 行为 |
|---|---|
| 开局要等两人的石头配额都满足才进入建墙；先满足配额的人可能在墙边等待 | 每人满足自己的石头配额即可施工，另一人继续采石；剩余墙材料已由同伴持有时，空手工人继续采收入矿；没有可达石矿时临时采其它矿，石矿恢复后再优先筹石 |
| 行走阶段把建筑目标存为坐标元组，实际交互阶段又存成单个坐标；墙位每轮按距离重新选择 | `interact`在行走和操作阶段都记录同一个 `Pos` 目标；优先完成自己的有效墙位，不抢另一名携石工人的施工目标 |
| 最后一两个白天回合仍向远处墙位出发，入夜禁建后再改去采矿 | 施工前要求“到邻格的路线步数 + 1个建造回合”不超过剩余白天时间；不足时继续采矿，避免发起无法完成的施工行程 |
| 另一工人的矿点声明优先于自己正在进行的有效采矿行程 | 先保留自身有效矿点，再为新行程考虑错开矿点及价值/距离；矿耗尽、停矿、失败冷却、不可达或路径暴露时重新选矿 |
| 即使队友无法侧移，寻路仍把请求者的本轮标记为已用 | 仅在队友实际安排侧移或已安排离开时协作等待；让行失败返回 `False`，调用方可以尝试其它目标或工作 |
| 两名工人同时奔赴同一批升级券，购买完成后另一人半途折返 | 每种待购物品保留一名采购工人，其他工人继续经济任务；按现有批量需求与共享金币预算买，不增加第二次无效商店行程 |

开局仍先建三座火箭，然后筹集墙材料。变化是采石与施工可由两人并行，不再把“所有石头收齐之后才允许第一块墙”当作同步屏障。未承担剩余材料任务的工人可以在同伴施工时采铁/铜；满包时仍保留墙所需石头再售矿。

## 函数与状态

| 位置与函数 | 参数/状态 | 用途 |
|---|---|---|
| `src/agent/brain.py` `interact(role, target, command, footprint=None)` | `target: Pos`为交互建筑；`footprint`仅决定合法相邻站位 | 任务目标在走路和实际交互时保持同一身份；动作成功加入计划后才登记 |
| 同上 `opening_worker(role)` | 仍使用 `stone_targets()`按观察背包分配配额 | 独立筹石/施工；没有施工任务时尝试经济采矿 |
| 同上 `build_wall(role)` | 上轮 `build:wall`目标、目标占用、剩余日照 | 保留有效施工目标，并检查行程能否在本日完成；目标完成或失效后选择新墙位 |
| 同上 `mine(role, need_stone=False)` | 有效矿点、风险、闭矿/失败冷却、价格、上轮采集目标 | 已进行的有效采矿行程优先；`need_stone=True`仍只选择石矿 |
| 同上 `buy_upgrade(role)` | `purchase_claims`是本轮物品声明集合 | 只在实际购买、移动或有效协作等待成功后登记采购责任 |
| `src/agent/worker_coordinator.py` `target_owned(role, target, kind=None)` | 可选任务类型；建墙所有者还需持有石头 | 对施工按目标分工，不把无材料工人的旧目标永久锁住 |
| 同上 `purchase_owned(role, name)` | `worker_tasks[uid].purchase_item`、任务类型与轮次 | 识别同种物品的既有采购工人；死亡、任务过期、满包或夜间维修职责会释放责任 |
| 同上 `move_to(...)` | 原合法站位、`allowed`范围及夜间风险约束 | 失败尝试不会抢占本轮动作；有效协作等待的 `moving=False`，避免把等待误报为移动卡住 |

`purchase_item`只在 `kind == 'buy_upgrade'` 且记录仍新鲜时生效。任务字典仍存于当前进程的 `GameMemory.worker_tasks`，死亡和过期清理沿用原规则，不依赖 `temp/` 或磁盘文件。现有 `worker_motion` 中的 `target` 可直接观察施工/采矿目标是否稳定。

## 验证与边界

`tests/test_worker_efficiency.py`的10项测试覆盖材料分工、空手工人继续采矿、石矿暂缺、第70→71回合施工截止、完整施工行程目标、无法让行时释放动作、同种升级券单人采购跨黄昏、同伴使用同矿时的目标保持、失效/危险矿点重选、镜像下两名工人保持不同施工目标。原先五个问题场景、重复采购和石矿暂缺场景分别在对应修正前失败。

开局原有两项全流程用例更新为并行筹石/建墙的需求：仍验证三火箭先完成、墙消耗实有石头、确切U形墙与镜像、黎明/黄昏规则和无非法移动；不再要求最后一次采石必须早于第一块墙。其余寻路、让行、夜间维修、升级与任务用例保留。

本地结果见[v1.0.1验证报告](../../reports/VALIDATION-v1.0.1.md)。矿点消失、敌人逼近、需要紧急维修或材料/需求变化仍可合理打断行程；本次没有完整官方对局数据，也不声称任意地图永不等待或给出挖矿收益提升百分比。
