# v1.2.14 多 BOSS 进位与基地直射

> 当前建家与维修已更新为[v1.2.15永久封闭与采石](SEALED_HOME_V1215.md)：取消临时入口、门石和自动拆门预算；工人从外侧施工/维修。购物截止、真实任务成功数购用、普通单位视野及BOSS战斗框架继续沿用。下文涉及旧临时门或墙内返回的描述仅供历史追溯。

本版只调整第一天夜晚的 BOSS 操控。此前采购工人的购物截止、开拓者任务二→任务一→任务二、普通单位侦察与首日建设策略沿用 v1.2.13。新增模块 `src/agent/boss_formation.py` 配合 `robot_raider.py`，使前排 BOSS 在保留基地射线的同时优先进驻对方共同操炮位，后排优先寻找可直接攻击基地的实际可达站位，避免先拆本可绕开的墙。

规则参照 [v2.0任务书](../../32_docs/任务书.md) §4.3、§4.5.4、§4.7.3 和 [接口文档](../../32_docs/接口文档.md) §2.1–2.2。机器人射程为切比雪夫距离 3，即当前格周围边长 7 的方形区域；同回合只能移动或攻击。召唤机器人不提供视野，敌基地和墙全局可见，炮台及普通角色仍需己方普通单位真实共享视野。45°射线只检查对角线上的遮挡格，邻接在两侧的墙不额外封闭此射线，这是用户已确认的实战补充。本次是团队策略修正，未改写官方原件。

## 原始日志与根因

用户提供 `temp/boss_attack_log.log` 和两张前后排示意图。原始日志保留在 `temp/`，正式程序与回归测试不读取这个路径。下面区分日志中已经发生的事实与源码决策问题；本版本地验证不能替代新官方比赛。

| 日志位置 | 已观测事实 | 对决策的影响 |
|---|---|---|
| R78 | 前排 31035 在 `(6,21)` 攻击基地格 `(9,21)` 成功；后排 31036 在 `(5,21)`，到基地最近格距离 4，先走到 `(6,20)` | 后排这一轮确实超出射程，不能把此时的移动认定为“原本可以直射却不打” |
| R79 起 | 后排从 `(6,20)` 可以再走一格到 `(7,21)`，之后直接攻击基地；旧代码却先选 `base_weapon_obstruction`，攻击墙 40017 `(7,20)` | 寻找可达清晰基地射击站位的优先级低于原位拆障，一步进位被约 25 次拆墙攻击替代 |
| R79–R85、R94–R111 | 对墙 40017 共持续攻击 25 回合；R112 观测墙移除 | 这是实际造成的时间消耗，不代表墙不可绕过 |
| R86–R92 | 敌方开拓者返回武器附近操炮 | 只在基地外侧打基地没有封住共同操炮位；前排可尝试进入并占住该位置，降低对方回到单人操三炮位置的机会 |
| R125 | 历史其它基地射线的两次失败触发旧的全局 `needs_close`；新射线 `(7,20)→(9,22)` 即使本地检查清晰，也被迫继续移动 | 失败历史被扩大为“这个机器人所有远处基地射线都不可信”，导致未失败的新射线不能直接尝试 |

这局敌基地 10013 的传入左上角是 `(9,22)`，其真实 2×2 格子为 `(9,22)`、`(10,22)`、`(9,21)`、`(10,21)`。三座炮台 10040、10041、10042 分别在 `(8,20)`、`(9,20)`、`(8,22)`，共同操炮位是 `(8,21)`；墙 `(7,20)` 和 `(7,22)` 之间的入口为 `(7,21)`。前排进入入口后再进入共同操炮位，可以继续保留通往基地的射线，并给后排留下攻击站位。

在前述进位时段，普通侦察工人在 `(6,19)`、捣乱鬼在 `(4,19)` 可真实覆盖入口和操炮区域。R125 时这些普通视野来源已经死亡，因此日志不能证明新的候选落脚格无人，也不能把某次失败直接归因于隐藏单位。基地虽全局可见，空格是否被隐藏角色占用仍需实际移动回执确认。

## 当前决策顺序

1. 每回合先重新读取当前真实可见、炮台周围一格内的存活工人和开拓者，优先清炮手。回血后仍是存活目标，不能因上轮攻击就认定死亡。已有有限追击、单墙突破及过长绕路回退保留。
2. 没有可执行的炮手优先动作、转攻基地时，检查基地 2×2 的所有格子及当前站位射线。单只 BOSS 或无可见安全进位格时，仍直接攻击当前可射到的基地格子。
3. 多只存活、未眩晕 BOSS 协作时，按到基地 footprint 的最小切比雪夫距离、机器人 ID 排序。前排先调度；附近有另一只 BOSS 时，优先选择真实见过炮阵推导的共享操炮位。操炮位至少能操控两座炮，三炮共同位置优先。
4. 前排每次只移动一格，落脚格须在当前实际路线中可达、被普通单位真实视野覆盖，并且存在未被失败缓存排除的清晰基地射线。每步必须更接近基地，或保持基地距离但增加能操控的炮台数；已占共同操炮位时原地攻击，不为并列候选位置来回挪动。
5. 没有符合条件的共同操炮位路线时，前排可选择真实可见、比当前更近、落脚后仍能直射基地的一格。没有这样的格子就保留原位攻击。第一夜最后一回合不为编队放弃当前攻击。
6. 后排不能原位攻击基地时，先找当前真实占用下实际可达的清晰射击站位；剩余夜间必须足够走到并至少攻击一轮。找到则先移动，下一回合重新读取实际位置与射线后攻击。只有没有可执行直射路径时，才继续原有炮台清障或破墙。
7. 若本回合同伴已经发出 `move`，其旧位置或本轮预约暂时封路，后排可用去除这些同伴格子的诊断路线判断是否存在 3 步内的基地直射站位。成立则原地等待，连续最多 3 轮；诊断结果不是新视野，也不会据此直接走进同伴当轮仍占用的格子。下一观测重新检查，正常移动或攻击会清零等待次数。

上述前排移动是一项策略取舍：用一轮攻击换取持续直射站位和共同操炮位占用。占位不能保证敌方完全无法操炮；对方仍可能在其它邻格操控部分炮台，敌人也可能重新进入视野或改变防守位置，仍须逐回合检查。

## 函数与参数

| 文件 / 函数 | 参数与返回值 | 职责 |
|---|---|---|
| `brain.py: Strategy.run()` | 使用当前 `Turn`、`ActionPlan` 及 `RobotRaider` | 按 `BossFormation.ordered_robots()` 的近基地顺序调度，本回合前排移动指令先进入动作计划，后排才能判断真实预约 |
| `boss_formation.py: BossFormation(raider)` | `raider` 为当前 `RobotRaider`，复用其 `turn/plan/memory` | 不建立独立视野或预测地图；编队逻辑是原 BOSS 决策的一部分 |
| `base_distance(position, base)` | 当前 `Pos`、敌方基地 `Unit`；返回整数距离 | 以基地全部 2×2 格子取最小距离，避免仅到传入左上角计算 |
| `ordered_robots()` | 无显式参数；返回已排序本方召唤机器人列表 | 距基地更近者先调度，同距离按真实机器人 ID 稳定排序；类型、HP、眩晕权限仍由 `decide()` 检查 |
| `clear_base_cells(robot, base, position)` | 当前机器人、基地、候选站位；返回可攻击的基地 `Pos` 列表 | 将候选站位代入已有射程/真实目标/墙和建筑遮挡检查，并排除该机器人在该站位已失败的射线 |
| `advance(robot, base, route)` | 当前机器人、基地、当前真实 `Routes`；返回是否加入合法移动 | 仅给符合条件的多 BOSS 前排进位；共同操炮位优先，保留基地射线，禁止隐含移动加攻击 |
| `wait_for_lane(robot, base)` | 当前机器人、基地；返回是否原地待命 | 只诊断本轮已命令移动的同伴，忽略其旧格和预约仅用于判断短等收益；最多连续 3 轮 |
| `robot_raider.py: attack_base(robot, route, fallback=None)` | 当前机器人、实际路线、可选追炮手回退原因；返回动作是否加入 | 保留清炮手后的次要角色判断；原位直射、前排编队、可达清晰射击格、短等、炮台/城墙清障依次衔接 |
| `firing_plan(robot, points, route)` | 机器人、目标坐标序列、实际路线；返回最优站位元组或 `None` | 穷举射程 3 范围内实际可达、弹道清晰且未失败的射击站位；受单回合计算截止约束 |
| `observe_feedback(robot, old)` | 本轮机器人和上轮任务状态；原位更新缓存 | 只有真实 `False` 攻击反馈记录失败；不因缺反馈或伤害推测盲目扩大失败范围 |
| `firing_key(target, post)` | 目标格、射击站位；返回 `(target_id, target, post)` | 失败绑定目标 ID、落点和本方原站位；其它未失败射线仍可尝试 |

参数没有新增到比赛请求或外部配置。编队范围采用另一只 BOSS 距敌基地至多 6 格，共同操炮位至少覆盖 2 座炮，后排临时通路诊断至多 3 步、连续等待至多 3 轮。这些是当前团队策略常量，不是官方新增规则。

## 状态与日志

`GameMemory.robot_raids[robot_id]` 继续保存真实上一轮 `position/action/target/round`、`failed_firing`、`verified_base_post/verified_base_target`。本版不使用跨站位的全局“必须贴近基地”条件。失败静态射线仍保留原有有效期与建筑几何变化失效规则；失败移动格仍独立记录和重新检查。

新增 `formation_goal`、`formation_action` 用于保持进位目的，`formation_wait_rounds` 用于限制连续待命。它们不替代实际位置，也不认定移动已成功；机器人死亡或第一夜结束后沿用原任务清理流程。

| `robot_diagnostic` 字段 | 解释 |
|---|---|
| `formation.front_id` | 本轮按距离和 ID 选出的前排 |
| `formation.action` | `occupy_operator_post`、`advance_to_base`、`holding_operator_post` 或 `wait_for_observed_teammate_move` |
| `formation.post/next_step/control_count` | 目标共同操炮格、当轮一格落点、目标格可操控的已知存活炮数 |
| `formation.current_base_distance/next_base_distance` | 前排移动前后对真实基地 footprint 的距离 |
| `formation.next_direct_base_cells` | 落脚格可直射的基地格子；仅是当前规划检查，最终仍须动作回执 |
| `formation.moving_ids/wait_rounds` | 后排短等时已收到移动指令的同伴及连续等待次数 |
| `base_reposition` | 后排先走到清晰基地射击格的 `post/target/cost`，原因 `reachable_clear_base_before_obstruction` |
| `base_failure_scope` | `exact_target_and_firing_post`，说明失败仅封禁原射线 |
| `base_close_required` | 固定 `false`，保留旧日志字段兼容，不再作为强制靠近判断 |
| `direct_base_cells/failed_cache` | 当前原位可射格与真实失败射线，便于核对“为何攻击、进位或拆障” |

`waiting_for_boss_lane` 是原地待命的最终原因，没有输出移动或攻击指令。实际指令仍只有一个 `move` 或 `attack`；命令被 `ActionPlan` 接受只能说明本地合法性检查通过，实际移动和伤害需要下一回合的 `action_results`、机器人位置以及目标 HP 验证。

## 验证入口与范围

`tests/test_boss_formation.py` 使用手工可核验观测检查原日志缺口、前排进入共同操炮位、后排优先直射位置、45°弹道、同伴真实占用和预约、眩晕及单只机器人、没有普通视野和失败缓存；具体测试集合以验证报告为准。原相关 BOSS 回归继续保留清炮手、炮台首障碍、无炮台后的原位近基地角色与反馈判断。

仅进行第一天本地测试和逐帧 HTTP 检查，结果及源码哈希见[验证报告](../../reports/VALIDATION-v1.2.14.md)。原用户日志属于修正前的真实对局证据；新版本在官方双队对局的效果尚未由这些本地检查证明。
