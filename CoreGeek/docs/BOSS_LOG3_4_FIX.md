## 修复设计

`robot_raider.py`保留曾真实观察到的敌方静态建筑快照。机器人接近不清除记忆；只有己方存活普通角色/建筑的视野确认空位、全局可见的基地/城墙实际消失、直接死亡信息或新的实际建筑信息才更新。记忆用于路径占格、射线规划和识别真实可见炮旁英雄，不向`teamEnemy.roles`注入隐藏单位，不创造可攻击目标。

静态目标的失败落点/站位组合在首夜保留，建筑几何改变时重新评估。基地攻击连续两次失败后选择近邻射击位；这是恢复策略，BOSS官方射程仍为3。成功攻击记录已验证站位和落点，炮手优先打断后可以返回；同一组合再次失败立即撤销。移动明确失败且位置未变时，下一步短期禁用，重复无视野失败延长，普通角色/建筑确认空位可释放。

`site_blockade.py`改为内侧绕过恶意占点：正面/侧翼直线缺口用三块内墙，正面角缺口用一块内对角墙。右基地`(30,10)`的`(28,7)`缺口对应临时墙`(29,8)`，工人必须先让出该格。两工人分配不同施工目标和采石工作，原缺口保留一块石头。以实际观察到围墙为封口依据，拒绝反馈不算成功且该位置不重复建造。白天原墙补齐并观察确认后才能拆临时墙；夜间不发非法build。

`first_night_defense.py`负责首日独立守家岗。三炮与有效围挡完成后，先准备至少一台2级火箭及默认5个维修包；BOSS采购预算先扣除尚缺的这部分防守费用。观察工人只有在实际防守准备完成、能够赶上入夜时才出发。守家工人提前往返商店，按路径和交互耗时回防，首夜在墙内巡修；原占点预留石头继续保留。第二天及以后沿用既有升级、经济和维修策略。捣乱鬼观察路径避开可见敌普通角色的邻格，并优先留出一回合移动余量。

## 后续日志与验证

关键开发接口：

| 文件/函数 | 输入与返回值 | 职责 |
|---|---|---|
| `first_night_defense.FirstNightDefense(strategy)` | 当前`Strategy`，共享`Turn/ActionPlan/GameMemory` | 只处理第一天，固定守家工人；构造时不依赖后构造的袭击对象 |
| `closed() / prepared()` | `bool` | 分别检查实际防线封口、首夜火箭/指定守家工人包库存；不把本轮命令算成实物 |
| `reserve_gold()` | 尚缺最低防守物品的实际金币费用 | 购买BOSS及其它升级时保留，已持有及已预约购买部分不重复预留 |
| `needs_supply(role) / worker(role)` | 实际`Unit`；`bool` | 允许封口后的占点待命者去备包；接管守家工人当轮动作，夜间使用既有内侧巡修 |
| `robot_raider.observe_structures()` | 当前真实敌单位及己方存活普通单位视野 | 更新`GameMemory.enemy_structures: dict[int, Unit]`；记忆不等于当前可见攻击目标 |
| `observe_feedback(robot, old)` | 实际机器人与其上一轮独立任务字典 | 关联紧邻回合False/True，维护静态射击缓存、基地恢复和失败移动格 |
| `raid_scouts.scout_route(role)` | 工人使用原路线；imp使用附带避捕格的`Routes` | 不经过当前可见敌普通角色的八邻格，暂时无法找到观察站位时尝试安全退让 |

本地配置`enable_first_night_defense`默认`true`，只控制新增首日流程，不关闭原三炮/U墙和后续维修。`first_night_repair_stock`默认`5`、允许1–100并受工人容量限制；它与第三天起使用的`repair_stock/repair_stock_per_day`独立。`repair_threshold_percent=30`及`return_margin=4`沿用。`boss_controller_max_walk=4`继续控制追炮手的预算，与失败后近位恢复不同；没有新增官方请求字段。

新增`defense_diagnostic`记录己方实际基地/墙HP、永久缺口、临时围挡及失败点、守家身份、包库存、准备状态和预留金币。原`robot_diagnostic`增加记忆建筑、失败次数、近位恢复、成功站位及被禁用的移动格。日志不改变HTTP响应，不记录隐藏角色猜测。

本地回归覆盖两日志中的失败序列、镜像角绕墙、材料死锁、失败施工反馈、首夜预算/供应/回防与观察者避捕。合成负反馈只能证明不会复现原循环，不能保证新站位一定命中；实际伤害、视野、临时建造区及首夜防守强度仍需官方对局验证。验证结果见[本地验证报告](../../reports/VALIDATION-v1.2.5.md)。
