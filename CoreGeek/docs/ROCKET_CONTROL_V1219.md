# v1.2.19 三火箭阵型的 BOSS 攻击与占位

本版只调整第一天夜晚的 BOSS 决策。敌方已确认阵型为三座火箭发射台时，BOSS 只把同时可以操控三炮的共同位置上的敌方可控单位作为人员攻击目标；其它炮旁、基地旁或途中的工人、开拓者不再引起追击。共同位置没有敌方可控单位时，优先尝试占住可用共同位置，随后攻击敌基地。混合炮阵和不足三座火箭的情况保留既有策略。

这是用户指定的团队策略优化，不是官方新增攻击权限。规则依据为 [v2.0任务书](../../32_docs/任务书.md) §4.3、§4.5.4、§4.7 和 [v2.0接口文档](../../32_docs/接口文档.md) §1.3–1.5、§2.1–2.2。炮台由周围一格的角色操控，距离使用切比雪夫距离。BOSS 射程三、不能在同一回合移动并攻击、召唤机器人不提供视野，以及恰好 45°射线不额外检查两侧墙体，继续采用用户已确认的比赛说明。官方原件和 temp 原件均保留，正式程序不依赖 temp。

## 阵型判定与目标范围

炮位知识来自真实观测后保存的 `GameMemory.enemy_weapon_sites`，并结合真实建筑记忆；失去当前视野不使已确认的炮位变为未知。新的实际炮台类型观测覆盖同位置旧类型。三火箭模式要求敌基地武器圈内已经确认恰好三个不同位置，而且三个位置的类型全部为 `rocket`。未知炮型、混合炮型和不足三炮都不启用本策略。

共同位置集合按三个炮位分别计算距离一范围，再取交集：对每个候选 `p`，必须满足 `distance(p, gun_pos) <= 1` 对三炮全部成立。基地四格、炮位、墙体和其它固定障碍不成为占位目标。集合可能包含多个格，也可能为空；空集合表示三火箭已确认但没有合法共同操炮位，不回退为攻击任意炮旁人员。

人员目标只能来自当前 `Turn.enemies` 中存活的敌方可控单位。工人、开拓者以及位于共同位置的捣乱鬼均按实际观测判断，旧单位位置或推算炮手位置不产生攻击目标。角色从共同位置走到其它格后，下一轮立即失去本模式中的人员目标资格；回血、未死或新单位进入共同位置时重新判断。

例如三个火箭位于 `(8,20)`、`(9,20)` 和 `(8,22)`，共同位置是 `(8,21)`。当前敌工人在 `(8,21)` 时可清理；位于 `(9,19)` 的工人虽然邻接两座火箭，也不因炮台邻接被追击。共同位置失视时仍可由炮位几何确定，但不能凭此向该格盲目攻击人员。

## 每回合决策

1. 读取实际 BOSS 位置、状态、上一轮动作结果和当前建筑几何。第一夜之外、白天、死亡或眩晕时沿用原跳过条件。
2. 判定三火箭模式及全部合法共同位置。仅筛选当前可见、存活且实际位于这些格上的敌方可控单位作为炮手目标。
3. 对合格目标沿用原有射程、清晰弹道、有限追击和必要拆障检查。人员优先级不放宽攻击合法性；不可达或追击过长时仍可转攻基地。
4. 无需清理共同位置上的敌人时，尝试进入一个实际可达、未被真实单位和当轮预约占用的共同位置。单只和多只 BOSS 都可进位，前排先安排动作，其余 BOSS 各自依据实际占用重新选择。
5. 已经占住共同位置的 BOSS 保持位置并尝试攻击基地，不为并列位置来回切换。共同位置必须可达、移动后剩余夜间足以至少攻击一轮，且目的位置能直接攻击基地；如果当前已经能直射基地，本次下一格也必须保留基地射线。已知炮位允许失视后继续规划占位，未见过的隐藏动态单位仍可能导致移动失败，由下一轮实际动作回执处理；不会把同伴本轮将离开的旧位置当作已经腾空。
6. 没有可执行的共同位置进位动作时，继续基地直射、寻找可达射击站位、必要清理挡住基地射线的武器或城墙。三火箭模式不因为敌武器已被摧毁而重新启用基地周围人员追击。

占位使用本回合唯一的 `move`，下一轮再从实际位置判断 `attack`。当前射程内有合格炮手时先处理炮手；共同位置无人时以占位和基地伤害为目标，减少无关人员引起的反复换向。占住一个三炮共同位置不等于敌方完全无法操控任何单炮，其它邻格仍可能操控部分炮台。

## 源码入口与参数

| 文件 / 函数 | 参数与返回 | 作用与维护要点 |
|---|---|---|
| [robot_raider.py](../src/agent/robot_raider.py) `RobotRaider.rocket_control_posts()` | 无参数 → `tuple[Pos, ...]` 或 `None` | `None` 表示不启用三火箭模式；元组表示启用，空元组也不得回退宽泛人员选敌。使用真实已确认炮位、类型和敌基地几何。 |
| 同上 `decide(robot)` | 当前本方 `Robot` → `bool` | 当前可见人员筛选、有限炮手追击和基地分支。True 表示已安排本轮动作或策略待命。 |
| 同上 `attack_base(robot, route, fallback=None)` | 当前机器人、真实 `Routes`、可选回退原因 → `bool` | 三火箭模式尝试共同位置进位后攻基地，并抑制旧的基地旁人员攻击；混合阵型保留原分支。 |
| [boss_formation.py](../src/agent/boss_formation.py) `BossFormation.occupy_rocket_post(robot, base, route, posts)` | 当前 BOSS、敌基地、真实路线和共同位置集合 → `bool` | 单只或多只 BOSS 的安全进位辅助；保留真实占用、逐步移动和基地射线检查。`posts` 为共同位置元组，`route` 保留当前占用和预约；True 表示已输出唯一的移动指令。 |
| 同上 `ordered_robots()` | 无参数 → 本方机器人列表 | 到敌基地占地更近者先调度，同距按真实 ID 稳定排序。 |
| [app/service/memory.py](../app/service/memory.py) `GameMemory.enemy_weapon_sites` | `dict[Pos, str]` | 永久炮位及最新真实炮型知识；不提供活角色 ID、血量或视野。 |

不新增用户配置项，也不改官方 `roleCommandMap`、`controllerId` 和 `targetPos` 字段。机器人攻击仍以实际机器人 ID 为键，不带武器操控者字段；所有动作继续通过 `ActionPlan.add()` 校验。

## 验证与排查

本轮只进行第一天的本地验证。检查三火箭共同位内/外角色、工人/先锋/捣乱鬼、人员离位或回血、纯缓存炮位、多个共同位与空集合、单 BOSS 和多 BOSS、镜像布局、真实占用与 45°弹道，以及混合炮阵旧策略。准确检查数量、源码哈希和连续 HTTP 结果见 [VALIDATION-v1.2.19](../../reports/VALIDATION-v1.2.19.md)，这些不代表新版官方对局成绩。

排查时将 `robot_diagnostic` 中的 `targeting_policy/rocket_control_posts`、真实可见单位及候选资格、`formation` 进位动作、实际基地射线和下一轮动作反馈一起检查。`targeting_policy=three_rocket_control_posts` 表示启用本策略，`weapon_neighbours` 表示原选敌逻辑；进位动作为 `occupy_rocket_control_post`，已占位为 `holding_rocket_control_post`。已有炮位只能解释共同位置为什么被选中，不能证明该位置当前无人或证明某个旧炮手仍然存活。历史行为和模块演化见 [多 BOSS 进位](BOSS_FORMATION_V1214.md) 与 [开局侦察和炮位记忆](OPENING_SCOUT_V1218.md)。
