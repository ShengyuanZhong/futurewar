# v1.2.22 邻格抓捕与首日反侦察回防

本版增加开拓者和工人的邻格抓捕：任何昼夜，当前八邻域内存在存活的敌方捣乱鬼时优先发送 `catch`。第一天，开拓者完成任务二→任务一→任务二三次尝试后回防，采购工完成召唤券购买与使用后也回防；发现己方基地附近的敌方捣乱鬼时尝试接近并抓捕，减少其为敌方机器人提供共享视野的机会。没有可追目标时，开拓者继续原操炮流程，采购工回到可达外侧维修区后继续原补给与维护。

本次是用户指定的策略调整。抓捕规则依据 [v2.0任务书](../../32_docs/任务书.md) §4.3、§4.4，以及 [v2.0接口文档](../../32_docs/接口文档.md) §2.2–2.3：所有角色可抓捕周围一格的敌方捣乱鬼，成功后队伍获得20金币、目标死亡；双方捣乱鬼同回合互抓时双方均死亡、各获20金币。范围是八邻域，包含斜向相邻格。正文未给抓捕增加昼夜、冷却或墙体弹道限制，本版不自行增加这些条件。

## 邻格抓捕与动作优先级

自动抓捕只接入存活的开拓者和工人，捣乱鬼的首日侦察、避捕与后续毁矿策略保持原流程。`ActionPlan` 接受任何可控角色提交合法 `catch`，策略的自动分工不缩小官方权限。

抓捕指令使用实际角色ID和当前敌方捣乱鬼坐标：

```json
{"action":"catch","targetPos":[{"x":10,"y":20}]}
```

只有当前观测中的敌方 `imp`、血量大于零且与抓捕者切比雪夫距离恰好为一时才发送。死亡角色、己方捣乱鬼、其它敌方角色、旧坐标与推断位置都不是合法目标。每角色每轮只能执行一个动作，抓捕优先于使用药剂、任务动作、购买或使用召唤券、施工、采矿、移动和操炮；本轮抓捕后不追加其它动作。机器人仍只使用自身原生 `move` 或 `attack`。

发出指令不等于已经抓到。目标是否死亡和20金币是否到账依下一轮官方观测及动作反馈判断；不提前增加本轮可消费金币，也不让其它角色进入预计会被抓死的敌方占用格。任务奖励归因排除前回合抓捕带来的金币增长；任务服务桥接层让账本和用户控制器的成功经验归档共用奖励证据，避免账本记录失败、SOP/Skill却记录成功的差异。控制器原流程与prompt保持原样。

活跃任务期间的开拓者同样优先抓邻格敌方捣乱鬼。`TurnService` 在任务动作调度前检查抓捕；因抓捕推迟处理的LLM响应仅在仍是同一个任务时于后续回合恢复，不把旧答案提交给新任务。抓捕可能占用一轮任务时间，任务是否超时仍按官方当前任务状态处理。

## 第一日回防与追捕

邻格抓捕没有日数和地点限制。需要移动的主动追捕只用于第一天的回防角色，保留原开局分工：

- 开拓者仍尽可能尝试三次任务，顺序为任务二→任务一→任务二。三次实际尝试结束后，先处理基地附近的敌方捣乱鬼；没有目标或目标退出防区时，继续回到操炮位置。不能因为远处出现捣乱鬼提前放弃任务。
- 采购工继续按三次任务的成功数购买零至三张BOSS召唤券，并按原阵型方案逐张使用。完成采购和使用，或实际购用窗口结束后，才进入主动回防；存在待确认的购买/使用反馈或背包仍有BOSS召唤券时，不把防区追捕当作正常中止购用任务的理由。邻格即时抓捕仍可占一轮，下一轮重新评估购用流程。
- 侦察工不因为远处防区追捕改变敌后视野任务，但其邻格出现敌方捣乱鬼时也即时抓捕。己方捣乱鬼保持既有侦察与缺口接力策略。

防区使用当前存活的己方基地2×2占地及实际己方炮台周围四格，距离按切比雪夫距离计算。四格对应这些设施的共享视野范围，是本项目反侦察的策略边界，不是官方新增抓捕射程。敌方捣乱鬼只有在当前真实可见、存活且仍处于防区时才成为主动追捕目标。

追捕角色寻找目标真实八邻域中的可达空格，按当前建筑、NPC、矿石、角色和本轮目的格预约寻路；不穿墙、不拆墙，也不将敌方本轮未来移动当成既定事实。开拓者和工人共享动作预约，避免争抢同一落脚格。对方死亡、离开防区、失去当前视野或没有可达抓捕站位时，退出当前追捕并恢复回防流程，不沿旧坐标盲追到远处。

采购工购用任务结束后主动返回一次可达外侧维修区；必须确实部署过机器人或开始过赴店使命。零券且未出发、没有敌方捣乱鬼时保留原经济流程。只有真实观测到其到达，才记录 `buyer_home_arrived` 并恢复原补给、修墙或经济安排；同轮发出返程移动不代表已经到家。到达后不会每轮强制将正常补给路线拉回基地，新的基地附近敌方捣乱鬼仍可触发追捕。

双方同时移动，对手可以逃跑，墙体与角色占位也可能阻断追捕。实现提供合法抓捕和有限防区内的追赶，不虚构敌方位置或驱离结果，不能保证立即剥夺对方视野。

## 模块、函数与状态

| 位置 / 入口 | 输入与输出 | 作用 |
|---|---|---|
| [imp_defense.py](../src/agent/imp_defense.py) `ImpDefense(strategy)` | 当前 `Strategy` | 统一邻格抓捕、首日近家追捕与采购工返程，使用当前回合、动作计划和会话记忆。 |
| 同上 `catch_available()` | 无参数；直接更新动作计划 | 按开拓者、工人顺序检查全部存活角色的邻格抓捕，先于活跃任务和协作让行。 |
| 同上 `catch_near(role)` | 当前角色 → 是否已处理抓捕 | 发送合法 `catch`，占用本轮动作，记录实际目标和决策原因。 |
| 同上 `defend(role)` | 当前角色 → 是否已安排防守动作或待命 | 首日任务或购用流程结束后追捕防区目标，采购工无目标时处理一次返程。 |
| [actions.py](../src/agent/actions.py) `ActionPlan.add()` | 实际角色ID、指令字典 → `bool` | 校验单个 `targetPos`、可控角色权限、当前敌方imp及八邻域；不预测奖励。 |
| [brain.py](../src/agent/brain.py) `Strategy.run()` / `run_worker()` | 当前回合 | 即时抓捕放在普通动作之前，首日任务结束和采购工任务结束后调用主动回防。 |
| [app/service/turn_service.py](../app/service/turn_service.py) | HTTP回合调度 | 活跃任务分支也检查抓捕，保持每角色一动作与任务响应身份。 |
| [app/service/memory.py](../app/service/memory.py) `GameMemory.imp_defense` | 会话内策略字典 | 保存采购工真实到家记录和各角色本轮防守诊断；不缓存敌方imp供未来攻击。 |
| [app/service/task_service.py](../app/service/task_service.py) | 任务提交前后奖励证据 | 保留 `catch` 收入混淆排除，不因20金币误记任务成功。 |
| 同上 `_ObservedTaskController._submission_rewarded()` | 无参数 → 当前观察是否有任务奖励证据 | 继承用户控制器，只在桥接层统一任务账本和成功经验归档的奖励判断。 |
| [app/service/task_state.py](../app/service/task_state.py) `TaskAgentMemory.deferred_role_reply` | 当前任务被抓捕延迟的响应字符串 | 仅同任务且连续回合恢复，结束或换任务清空，不凭抓捕收入确认提交成功。 |

`buyer_home_arrived` 保存采购工实际到达维修区的回合数。每角色诊断说明当前决策、实际目标与回防状态；抓捕和移动均可在原回合响应中核对。`diagnostic()` 提供 `home_radius`、`protected_cells`、采购工ID、实际到家回合、当前可见imp列表及每角色 `reason/target/goal`；`TurnService` 使用 `imp_defense` INFO JSON输出，仍是调试信息，不新增官方字段。换队、重开局和角色死亡继续使用原会话隔离与真实观测，不把返程计划等同于成功。

不新增HTTP路由、官方请求字段或运行依赖。正式程序不读取 `temp/`，三任务顺序、召唤券成功数账本、阵型侦察、集中破墙、多BOSS基地集火及首日施工策略保持原规则。

## 验证与后续排查

本轮按用户要求只验证第一天：邻格及斜向抓捕、昼夜可用、非法目标与字段、活跃任务抢占、奖励归因、三任务和购用券前后的优先级、防区追捕与失视退出、采购工实际返程及不反复拉扯。准确检查数量、HTTP场景、源码哈希和未覆盖范围由 [首日验证报告](../../reports/VALIDATION-v1.2.22.md) 记录。这些是本地策略与接口证据，官方抓捕结算、对手逃跑及真实比赛中的视野压制仍需新对局验证。

排查时先核对敌方 `imp` 是否在本轮观测中、血量是否大于零、实际邻格距离和防区归属，再查看角色是否已抓捕或已有其它动作。采购工未回防时检查未完成的券、待确认反馈及购用窗口；回家后再次赴店属于原补给逻辑，不应仅凭离开维修格认定返程失败。
