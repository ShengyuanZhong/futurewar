# v1.2.13 首日采购截止与工人持续工作

2026-10-13。策略调整：首日白天两名工人均不再为回防预留返程时间；采购工人的商店采购与召唤使命优先于继续建墙。在仍有充足时间时可以照常施工，达到实际赴店和购用所需的出发截止后，即使普通墙尚未完成，也必须转入赴店流程。开拓者仍按任务二→任务一→任务二尝试，三次真正结束后回到操炮位。

此文描述团队策略，不改变 [v2.0任务书](../../32_docs/任务书.md)及[接口文档](../../32_docs/接口文档.md)。前版[采购工人分工](WORKER_BOSS_V1212.md)保留作历史记录；其中“必须墙齐才能出发”“首日黄昏恢复提前回防”的限制，以本版为准。

## 首日分工与优先级

| 角色 | 首日白天 | 任务结算后 / 首夜 |
|---|---|---|
| 开拓者 | 任务二→任务一→任务二，无购物或回防准入预算 | 三次尝试结束后回操炮位；不购买或使用 BOSS 券 |
| 采购工人 | 固定身份，先参与施工；墙齐或到达购物出发截止后前往实际商店 | 等三次任务真实结束，按成功数购买并逐张使用 0～3 张；不因黄昏提前回家 |
| 侦察工人 | 沿用实际建设完成后的敌阵探查、取车和两步驾驶；不为回家提前终止工作 | 持续提供普通单位真实共享视野，首夜沿用既有视野/避险逻辑 |
| 捣乱鬼 | 沿用侦查、破矿与缺口候补职责 | 原首夜缺口接替与真实占用检查保持 |

`buyer_id` 仍是固定的非侦察工人，不因购物距离、位置变化或同伴死亡而交换背包账本。采购工人在批准出发前可建墙；到出发截止时，建墙、常规经济、黄昏封门准备及维修回防均不能抢占采购使命。工人首日白天不因“再不回家就来不及”而折返，正常夜间限制和第二天后的维护策略保留。

## 实际购物预算

`BossRaid.departure_budget(role)` 的 `role` 是采购工人的当前 `Unit`，返回下面字段组成的预算字典；找不到可估计路线时返回 `None`。所有时间均为回合数，依据本轮真实坐标、通路、背包和驾驶状态重新估计，不把基地或商店假定为镜像。

| 字段 | 含义 |
|---|---|
| `travel` | 当前采购工人赴商店合法邻格的实际路径所需回合；已真实驾驶时按最多两步计算 |
| `opening` | 若受控入口确实封闭且需要拆门，预留实际 `remove` 的一回合，否则为 0 |
| `drop` | 为待购数量腾出容量所需的逐回合丢矿次数；每回合最多一件，等待真实背包更新 |
| `buy` | 尚需采购时预留一回合批量购买；已实际足额持券则为 0 |
| `use` | 尚需逐张使用的数量；三次任务尚未结算时按最多 3 张预留 |
| `slack` | 2 回合，供普通同伴让行或短暂路线变化 |
| `total` | `travel + opening + drop + buy + use + slack`，不加任何返程或回防时间 |
| `latest_departure` | `round_no + daylight_left - total`；首日即 `71 - total`，当前观测下最晚开始赴店流程的回合 |
| `post` | 选中的实际商店邻格 `Pos` |
| `route_mode` | 采用当前可达路线、需要同伴让行的诊断路线或拆入口后的预测路线 |

`departure_due(role)` 在剩余日照不超过预算总数时要求离开施工岗位。无可估计商店路线也会进入购物路线诊断，避免继续消耗白天窗口做低优先级施工。让行余量是规划参数，不能视为敌方持续卡位、任意任务耗时或任意地图下的官方完成保证。

封闭入口的预测只用于预算：真正出门仍必须先发合法 `remove`，下一观测看到墙已消失后才能通行。不能把预算内的虚拟拆墙结果写入当前地图，也不能透过己方建筑移动。每个角色每轮仍只发一条动作；同回合真实角色占用、目的格预约及车辆合法两段路径保持原校验。

如果到拆门位置的驾驶路径最后只走一格，按规则已经下车；预算中的拆门后路程随即按步行计算，不能继续假定双倍移速。

## 出发批准与施工事实分离

采购出发有两种合法的策略理由：实际建设达到原 `dispatch_ready()`，或实际购物时间已到截止。后一种只批准采购使命，不表示墙已完成。

`departure_authorized` 保存采购使命的出发批准，出发后持续锁定这次赴店/购用流程；不因后来某处墙缺失或敌方占点者离开而把采购工人拉回施工，减少走到一半折返。日志中的 `construction_approved_round` 只在真实施工条件成立时记录，不能因为购物截止而填写。`departure_round`、`departure_reason`（`walls_ready` 或 `shop_deadline`）和 `departure_budget_at_start` 用于追溯当时为何离开工位。

`Strategy.stone_targets()` 不把正在赴店、等待或购用的采购工人背包里的石头计入施工材料。剩余工人获得独立的未建墙采石配额，避免采购工携带剩余石头远行后，另一工人误以为材料已齐而只挖普通矿。

侦察工人的出发仍读取真实建设条件，或者既有基于真实施工批准的连续侦察状态；`raid_scouts.construction_verified_round` 保存真实施工确认。采购工人因截止提早出发不会自动批准侦察工人、不补造墙体事实，也不会让尚未完成的普通墙在侦察日志中变成“已建”。敌方基地和墙全局可见；炮台及可移动单位仍需普通单位视野，BOSS 本身不能承担侦察。

## 等待、库存和召唤

工人到店早于任务结算时，只行走或等待。开拓者三次任务真正结束且没有活跃任务阶段后，按成功记录冻结 0～3 张配额。失败尝试不算成功，金币充足不会越过配额；三次尝试未结束时不提前买券或用券。

购物继续读取本轮 `weaponShopList` 实价和队伍共享金币。券进入采购工人本人的背包；`pending_buy/pending_use.actor_id`、库存变化和实际反馈均绑定该工人。批量 `buy` 可一次购多张，`use` 则逐回合选不同合法出生点。容量不足仍逐轮丢低价矿，保留封门石及已有缺口补建所需石头，不丢维修包或升级券，也不假定丢弃已经结算。

召唤仍需真实敌方阵型与当前普通共享视野；购物截止不会取消视野门限，不对隐藏炮手或记忆角色坐标盲召唤。若捣乱鬼已安全提供所需的真实当前视野，则不必为了用券额外等待墙齐或侦察工人离家。首日日间窗口、每日最多 10 张、合法出生区、失败重试、缺反馈防重复及部分到账的实际账本沿用前版。

## 首日白天取消提前回防

| 模块 | 本版行为 |
|---|---|
| `DayGate.closing()` | 首日白天不进入按返程成本推算的提前关门阶段 |
| `GapDefense.preparing()` | 首日白天不为夜间肉身补位提前把工人调回 |
| `FirstNightDefense.trip()` | 首日白天只计去程与交互，不计返程；不能因回家预算不足放弃可执行工作 |
| `FirstNightDefense.worker()` | 首日白天没有末尾兜底提前回家分支；完成供应后继续可执行工作 |
| `WallGuard` 白天调度 | 首日不以维修岗回防职责抢占采购、施工或采矿 |

R70 若门负责人已经真实处于合法内侧、其他需要回防的角色也已在内，仍可以就地发合法 `build` 封门。不能为了封门给首日工人发提前回家命令，不能把已外派采购工人预测为在内，也不能在夜间补建墙。入夜后正常避险、维修、肉身缺口接力与侦察视野按既有逻辑执行。

## 开发定位与诊断

| 文件 / 入口 | 参数、返回及修改目的 |
|---|---|
| `src/agent/boss_raid.py: departure_budget(role)` | 输入当前采购 `Unit`；返回预算字典或 `None`，估计实际赴店、拆门、腾包、批购和逐张使用成本 |
| `departure_due(role)` | 返回购物截止是否已到；无路线时优先进入赴店诊断 |
| `worker_mission_active(role)` / `worker(role)` | 建设完成或购物截止均可启动；出发批准保持使命，采购优先于墙齐 |
| `dispatch_ready()` | 真实施工准入，维持三炮、实际普通墙及当前敌方占点忽略条件 |
| `src/agent/day_gate.py` | 区分首日无需提前返回与 R70 已就位才可封门 |
| `src/agent/gap_defense.py` | 白天取消首日预回防；夜间缺口实际占位和捣乱鬼接力保留 |
| `src/agent/first_night_defense.py` | 首日去程预算和供应后持续工作，取消白天兜底返程 |
| `src/agent/wall_guard.py` | 首日白天不抢回防，其它天继续原维护职责 |
| `src/agent/brain.py: stone_targets()` / `mine()` | 采购期间施工石独立分配；首日采矿不使用返程距离筛选 |
| `src/agent/raid_scouts.py` | 采购截止批准与真实施工批准分开，保持实际侦察准入及普通共享视野 |

`first_day_policy` 中可同时核对 `team_id`、当前 `dispatch_ready`、`departure_authorized`、`construction_approved_round`、`departure_budget`、采购工人位置与实际指令。`departure_budget_at_start` 解释当次批准；旧 `last_pioneer_decision` 仍为解析兼容别名，应按 `buyer_id` 与真实 `actor_id` 识别购用者。

本轮验证范围仍限定第一天。本地测试、HTTP逐帧观测和源码哈希见[首日验证报告](../../reports/VALIDATION-v1.2.13.md)；本地预算验证不代表已在官方双队对局中保证所有召唤按时完成。
