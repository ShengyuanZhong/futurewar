## 第一天开拓者的流程

两个己方任务点当日均已有确认接取记录，且当前phaseTask已经结束，才开始本流程。任务成功、失败或超时结束均可；不会做完一个任务就放弃另一个。接取记录由原任务模块持续维护，任务提示词、执行与经验归档不改。

1. 选择商店相邻站位，核对到店、购买一回合、使用一回合、返回操炮站位及原return_margin。返程对现有障碍作一次角色位置平移后的路径估计，不把直线距离当实际回防步数。时间不足、满包、商店无BossRobotSummonOrder或敌方正后方无合法候选时沿用原开拓者策略。
2. 到商店旁准备。按本轮weaponShopList实价购买**一张**BossRobotSummonOrder，文档价格120；购买前仍为未建齐的三座炮保留25/座。等待期间为这张券预留升级采购预算，剩余金币仍按原升级策略使用。临近日落必须停止等待并回防。
3. 下一轮真实背包出现券才使用，远程指定敌基地后方出生位置，无需本人去敌方基地。已确认取得一张券后，不因券异常消失再次购买。失败购买可重试；失败召唤且券仍在时排除失败位置再试。
4. 发出召唤后先返回原操炮站位，到位后交回原开拓者调度。夜间继续操控己方炮台，BOSS以自己的ID另发命令，不占开拓者动作。

只有第一天触发购买/使用；不会每天购买BOSS。当前保留了买券、用券各占一回合和午夜前返回预算。死亡、采矿收入不及预期、任务结束过晚或道路被堵时，不保证第一天一定能部署。

## 敌基地后方与出生约束

优先读真实teamEnemy.roles中的station。若缺失，以己方2×2基地完整占格作地图中心镜像：敌方左上角为 `(width-2-own_x, height-own_y)`，不能把左上角直接当单格镜像。

右侧敌基地的后方是+x，左侧是-x；预计后排操炮格仍分别为 `(base_x+3,base_y)` / `(base_x-2,base_y)`。出生点与预计操炮位分别计算：左侧基地优选 `(base_x-3,base_y)` / `(base_x-3,base_y-1)`，右侧基地优选 `(base_x+4,base_y)` / `(base_x+4,base_y-1)`。两组出生点关于2×2基地中心水平镜像，横向偏移变换为 `dx→1-dx`。

用户本次截图的基地左上角为 `(9,22)`，基地占 `(9,22)/(10,22)/(9,21)/(10,21)`，因此优选出生点是 `(6,22)/(6,21)`。截图蓝黄建造区整体为 `x=7..12,y=19..24` 的36格区域，等效于距基地2×2占格的切比雪夫距离≤2。41×32地图的180度镜像采用 `(40-x,31-y)`：该基地左上角变为 `(30,10)`，这两个出生点对应 `(34,9)/(34,10)`。使用真实敌基地坐标平移该模板，不写死截图的绝对坐标。

所有候选先接受合法性、待生成坐标和失败记录筛选，再按空地/动态占用排序，同档优先两个模板点。优选点被禁止、失败、pending排除或均动态占用时，可以选择同侧附近空格。不会在NPC、静态建筑或建造区内召唤，也不会反复使用已确认失败的落点。

召唤仍校验地图内、非NPC/任务点、非基地或静态建筑格、非本方待生成位置重复。角色、矿和机器人这类动态占用不使召唤自动非法，官方可旁移；实际出生位置始终读取下一夜的summonRobotList，不假定等于请求落点。

现有请求没有完整蓝黄建造区坐标（D01）。v1.2.1按用户截图证据，对双方基地固定排除距2×2占格≤2的完整36格区域，再排除显式规划建筑格和真实静态占用。`summon_build_margin`默认2；设置0或1不能缩小这条区域底线，显式设为大于2时仍扩大保守排除范围。6×6区域的坐标来自用户截图，官方正文只规定不能在任一基地建造区召唤，二者来源分别记录。后方无候选就不花钱买券，不扩大召唤规则或改写官方文档。

## 第一夜机器人流程

仅调度summonRobotList中HP>0的BOSS，使用真实ID；只在第一天夜间运行本策略。

- **每回合重新找操炮者**：检查本轮可见且存活的 `rocket/gatling/railgun` 周围八邻格，把其中存活的 `worker/pioneer` 作为当前操炮者候选。不会只盯一名先锋，也不会沿用上一轮的预测死亡结果。角色HP、位置、回血和炮台状态以本轮真实观测重新判断；观测没有敌方当前controllerId，邻格仍是可能操炮者的位置推断。
- **清空所有当前操炮者后再攻基地**：有合法直射目标时优先直接attack；候选间比较当前HP所需命中数/HP及实际走位成本，旧目标只用于稳定并列选择，不提高到其它可击杀目标之前。已有操炮者离开武器邻格后，不因历史锁定继续追离位角色。任一当前存活操炮者仍存在时，继续攻击、走位或破墙，不转攻基地；本轮没有操炮者候选时立即尝试攻基地。之后若工人或先锋重新进入武器邻格，即重新优先清理。
- **先调整位置再攻击**：射程3，选择可到达且到目标的线段不穿存活城墙的射击格；已有合法射线时直接attack。上一轮原生attack明确失败时，按目标ID、坐标和站位记录四回合失败缓存，同一格换了新角色仍可立即攻击。不会通过move+attack两条命令增加同轮行动。
- **无射击位置时破墙**：选择能打到的敌方墙，优先当前射线的第一道墙，再考虑靠近当前操炮者及破墙成本。下一轮重读角色与墙HP并重新选择目标，原墙未实际消失前不按已破墙处理。
- **以当前观测确认存活**：不会在发出一发攻击后本地扣HP并宣称击杀，也不会把暂不可见直接记作死亡。下一轮重新检查武器邻格内所有可见工人和先锋。没有可见操炮者时，尝试攻击全局可见的敌基地；不向旧角色的空坐标开火，也不额外插入后排侦察阶段。
- **终止/等待**：眩晕、死亡、第一夜结束或软截止到达时不发机器人命令；第2天白天清理机器人任务记忆。其它类型的己方可控机器人在本策略中待命，动作门禁已支持其move/attack，未来可单独加策略。

BOSS参数来自官方表：HP800、攻击力40、射程3；没有英雄近场操控要求。攻击指令不带controllerId，示例机器人30005用自身key和一个targetPos。射线采用项目已有的方格闭区间相交规则，擦角细节仍是D07，最终伤害由判题器结算。

## 归属与动作门禁

Turn新增summon_robots。其与robot.roles共享ID是正常情况：位置/HP/类型须一致，缺失于全场列表的己方条目补进统一占用集合，不能与英雄ID冲突，不能重复列出本方ID。机器人位置仍阻挡移动。

`hostile_robots()`排除这些己方ID，炮台积分/HP选点、伤害估值、工人危险图及法宝目标估值使用该集合。三级2+1及原比值公式继续保留，己方BOSS不当作取分目标。实际范围溅射/双方机器人受伤仍由判题器决定，本地只修正归属和估值。

ActionPlan分开保存英雄/建筑units与己方robots。机器人只能move/attack，夜间、未眩晕、每轮一次；移动八邻格并共享reserved，攻击一个可见敌方英雄/基地/建筑目标，射程≤3且无中间墙。不能借机器人命令占用英雄controllerId，也不能攻击己方英雄或隔着第一道墙打第二道墙。

召唤令use必须有一个targetPos，单日10张上限及已待生成位置不能重复。仅对连续回合且明确False的召唤失败释放本地尝试数/待生成位置；确认失败的出生点另记以避免重试同一地点。夜间首回合已进入生成阶段后清除白天待生成位置集合；不会硬编码新机器人ID。

## 模块与关键函数

| 位置/函数 | 参数与作用 |
|---|---|
| `src/agent/boss_raid.py` `BossRaid(strategy)` | 当前Strategy；day1购买/使用/返岗，观察实际背包与上一轮反馈 |
| 同上 `tasks_finished()` | 两个当日已接取点及phaseTask结束→bool |
| 同上 `shop_trip(role)` | Unit→可行总回合/去程/商店邻格，或None；包含购买、使用和真实障碍下的返程 |
| 同上 `pioneer(role)` | Unit→bool；本轮买券/用券/赴店/等待/返岗；到位后不抢原策略 |
| 同上 `budget_reserve()` | 给工人升级采购预留本次BOSS价格；不可部署时0 |
| `summoning.py` `enemy_base_position(turn)` / `enemy_rear_position(turn)` | 实际基地优先，2×2镜像后备，推算后排 |
| 同上 `summon_cell_legal(turn,settings,pos,pending=())` | 出生坐标、区域假设、待生成坐标；不限制物品使用者的远程距离 |
| 同上 `rear_spawn_position(turn,settings,pending=(),failed=())` | 后方合法候选排序，None表示无可用点 |
| `robot_raider.py` `RobotRaider(strategy).decide(robot)` | 原生Robot→bool；第一夜BOSS逐回合清理武器邻格操炮者、走位、破墙及攻基地 |
| 同上 `firing_plan(robot,points,route)` / `pursue(...)` | 候选目标、机器人当前路线；选择射击站位，必要时敌墙回退 |
| `robot_combat.py` `blocking_wall(turn,start,end)` / `clear_attack(turn,robot,pos)` | 第一阻挡墙、可见敌目标与射程检查，动作门禁与策略共用 |
| `protocol.py` `Turn.summon_robots` / `hostile_robots()` | 本方归属与敌方/系统机器人分离，全场占用仍合并 |
| `actions.py` `ActionPlan(...,summon_positions=())` | 注入跨回合待生成位置；robots独立权限，原英雄/武器权限保留 |
| `app/service/memory.py` | boss_raid保存状态/买用回合/出生点/失败点/已取得券/已返岗；robot_raids按ID保存目标/阶段/站位/最后观测；pending_summon_positions保存待生成位置 |

配置：`enable_boss_raid=true`（bool，关闭第一天购买和BOSS自动操控）、`summon_build_margin=2`（int，0–10，额外保守排除区域的工程参数；实际排除不小于距基地占格2格）。关闭策略不会回退v2.0召唤协议和归属解析。没有新增运行依赖或正式请求字段。

日志保留boss_raid，含购买/使用状态、失败点、原生机器人ID、controller/breach/base阶段及实际机器人命令；operator_snapshot每回合记录炮旁工人/先锋的实际ID/HP，controller_health记录当前目标HP，不能以发过attack当作已击杀。原任务与worker_motion日志保留。状态在当前进程按队伍事务保存；重启后不推断已经完成两个任务，但夜间仍可据真实本方BOSS列表独立操控。

## 本地调试与验证

当前回归重点是截图出生点及镜像、完整建造区边界、动态出生占用和失败点回退，以及多名工人/先锋操炮、每轮回血与死亡反馈、目标离开武器邻格、直射与走位选择、破墙后继续清理和缺目标立即攻基地。原归属合并/冲突、原生动作门禁、购买/使用反馈、返岗预算、多人移动预留和死亡/黎明/截止检查继续保留。执行结果与实际测试数量以[v1.2.1验证报告](../../reports/VALIDATION-v1.2.1.md)为准。

