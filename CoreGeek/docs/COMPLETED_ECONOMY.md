# 防线升级完成后的工人经济循环

v1.0.2，2026-10-09。用户要求工人在所有建筑升级目标完成后继续采矿、售矿、购买围墙修复包，晚上回防。本次“升级完成”仍由 `upgrade_policy.upgrades_complete()` 根据实际火箭/墙等级与存活状态判断，基地不加入升级目标。

## 原因与新的昼夜流程

旧版 `run_worker` 在 `WallGuard.full_time=True` 时，白天和夜间都提前交给维修模式。`final_daytime` 仅允许采购或回墙内待命，因此没有资金时也不会采矿来赚取后续维修费用；大量购买修复包还可能把背包填满，进一步堵住采矿。

现在两名工人完成升级后的白天均执行：

1. 先处理严格低于30%的危墙。
2. 按当前位置到城墙内的实际可达路径及 `return_margin` 判断是否该回防；黄昏停止外出经济工作。
3. 有可出售矿物且来得及往返时售矿，金币始终以下一轮官方观测为准。
4. 指定的一名采购工批量购买修复包；本人本批缺口满足后可把采购责任交给另一人，不要求先回城墙。
5. 其它时间继续挖矿。没有可达、能在白天预算内完成的矿点时，回到内侧等待。

夜间两人继续在墙内按上下责任区维修；不从岗位发起新的外出采矿或购物。次日白天重新进入上述经济循环，不能因为前一晚的岗位记忆永久停采。毁墙后的白天先恢复原补建/升级流程；夜间曾进入双维修的两人继续保护剩余防线。

## 背包与购买预算

`final_stock_targets`继续使用实时 `weaponShopList` 价格、共享金币、每日增长目标及昨日实际用量分配库存。每人的新增购包容量现在先预留 `min(sell_batch, capacity-1)` 个空格作为采矿空间；默认100格工人、`sell_batch=12` 时，空背包本批最多购买88包，而不是100包。

矿物出售先于买包，避免先用包占满矿物所在背包。已有修复包不会被丢弃；已有库存仍可超过新目标，预留只限制新增购买。资金、空间或往返时间不足时，不伪造购买，也不停止其它可行的采矿工作。

## 关键函数与状态

| 位置/函数 | 参数与作用 |
|---|---|
| `brain.py` `run_worker(role)` | 完成模式仅在夜间提前交给 `on_duty`；白天仍检查安全、建筑位清理，再由 `WallGuard.daytime` 调度 |
| `wall_guard.py` `final_daytime(role)` | 完成模式白天的抢修→返岗检查→卖矿→购包→采矿流程 |
| 同上 `trip_fits_daylight(role, landmarks, cells)` | 当前到交易点的路线成本+交易1轮+交易点至内侧的距离估计+时间余量，检查是否来得及往返 |
| 同上 `final_stock_targets(workers)` | 均衡分配可负担包数，同时保留一批采矿空位 |
| `brain.py` `mine(role, need_stone=False, return_cells=None)` | `return_cells`省略时沿用普通采矿；完成模式白天传内侧集合，要求前往矿点、至少采1轮、估计返程和余量能纳入日照预算 |
| `GameMemory.repair_supplier_id` | 本批补包采购身份；完成本批缺口或死亡后可换人，其他工人继续经济工作 |
| `WallGuard.full_time` / `full_time_repair`日志 | 保留的历史命名，表示已进入完成后的双维修模式；白天具体工作由 `worker_jobs/worker_motion` 显示，已不表示全天只维修 |

往返预算的去程和当前位置返岗使用当前路径，交易点/采矿站位的返程使用切比雪夫距离估计；未来占用变化可能导致提前中止行程。每回合仍重新检查日照和当前返岗路径，不对官方结算作本地假定。

## 验证

`tests/test_completed_economy.py`的四项回归在修改前失败，修改后通过，覆盖：两侧镜像下两人白天继续采矿；先卖矿、下一轮用到账金币按15金币/包批量购包；大量金币时保留采矿容量；两人黄昏返岗、夜间守墙、次日恢复采矿。原测试中“白天必须全天守墙”与“购包可以买满背包”的预期按新需求更新；夜间双人不同墙维修、严格阈值、补墙和升级顺序继续回归。
