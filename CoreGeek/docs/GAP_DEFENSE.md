# 合法建造、缺口接力与BOSS采购

v1.2.6，2026-10-10。依据用户本轮澄清和当前`32_docs/任务书.md`的蓝色武器区、黄色墙区及角色占格规则。用户已重新提供v2任务书原件；本轮只读，不改写。正式源码不依赖`temp/`。

## 建造范围与删除内容

基地为2×2，传入`pos`为左上角；占格为`(x,y)/(x+1,y)/(x,y-1)/(x+1,y-1)`。以到这四格的最小切比雪夫距离计算圈层：第一圈（距离1）只能建武器，第二圈（距离2）只能建墙。`Settings.build_cells`同时过滤默认U形阵和显式配置，不能以verified配置越圈建造。

删除了`site_blockade.py`及内绕/外绕墙授权、连续超过5回合的恶意判定、临墙施工材料分配、临墙封口确认、原墙建成后拆临墙等流程。`ActionPlan`仅允许建造`Settings.build_cells`中的位置，没有临时白名单。`GameMemory`不再保留`wall_blockades/temporary_wall_sites/blockade_worker_id`；旧围挡测试按已撤销的需求移除，新测试验证合法圈层与缺口接力。过去的绕墙描述只作历史记录，不能再作为当前策略。

原三火箭后排及12块U形墙本身均位于各自合法圈层，保留坐标、镜像、升级分组和开放后侧。

## 新的缺口处理

1. 本轮实际看到存活敌工人/开拓者/捣乱鬼站在尚未建造的规划墙位，立即记录缺口；不再等待6次观测。角色移走后，记录仍保留至原位置实际出现己方存活墙。
2. 白天两工先完成其它可建的原墙位。没有任何额外建墙或自动拆墙；已确认缺口不使开拓者购买/使用BOSS券失效。
3. 选择固定守家工人。优先沿用当前负责人、旧留守身份；避免把已派出的观察工人拉走。黄昏提前回缺口内侧邻格，仍可留一块石头供次日补原墙。工人去备包、挖矿时继续采用首日往返预算，临近入夜由缺口岗接管。
4. 夜晚原格仍被敌人占据时，只在内侧邻格等待，不发非法移动。原格实际空出后，工人移入规划墙位原地阻挡，不被普通避险、采矿、升级配送或友方让行派走。可在原格用Medicine回血，或用WallFixer修相邻低于30%的墙，但不为维修离开缺口。
5. 捣乱鬼提前回本方缺口附近待命。优先相邻格；角位的唯一相邻格被工人占据时，先在距缺口2格内侧等候，待工人进缺口后再靠近。白天避开工人施工邻格和正面单格维修通道。工人仍存活时，捣乱鬼不进入或穿过缺口；本轮实际看到负责人HP≤0或从存活角色列表消失后，才接替空缺位置。若仍有另一单位占格，继续等待，不能同轮穿过尚未结算的单位。夜间不改派另一采矿/观察工人代替倒下的负责人。
6. 第二天仍按实际观测操作。捣乱鬼/工人先让出施工格，携石工人在邻格等下一份空位观测或走位补原墙；工人不会因imp暂时占施工邻格就跑去采更多石头；只有观察到原墙确实存在才释放缺口职责，恢复普通维修、采矿、毁矿或侦察。工人按v2规则复活后可重新成为负责人。

同时有多个被占墙位时，当前一组工人/捣乱鬼优先负责正对基地的中间墙，再正面其它墙，再两翼；同优先级沿用既有目标。不会声称一组角色能够同时封住所有缺口。`other_walls_ready`仅表示三炮与其它墙位已实际完成；`FirstNightDefense.closed()`仍要求原墙全部真实存在，角色不能在日志中被算作已建墙。

正常情况下保留首夜工人观察/留守分工。遇到缺口时捣乱鬼优先本方待命；其它合法墙已完成且有守家负责人后，另一工人可继续去敌后为BOSS提供视野，不再等无法建造的墙或BOSS购买后暂时不足的维修库存。没有两个存活工人时不派出唯一工人。BOSS仍不提供视野，不伪造敌单位。

角色占格能阻挡机器人移动，任务书规定机器人会攻击阻挡单位。角色并不是具有城墙挡弹能力的建筑，接力只能争取防守时间，真实机器人选路/攻击及角色死亡仍由判题器决定。

## BOSS不采购的根因与修复

v1.2.5有两个新增硬门槛：`BossRaid.day_available()`要求`FirstNightDefense.closed()`，`available_gold()`又先扣至少一台L2和5个修包的全部费用。被占墙无法完成，而绕墙实际上不可建，所以第一个门槛永久为False；第二个门槛还会将120金币判成不足。本轮移除这两个采购门槛。

现在先保留尚未建齐三炮的25金币/座，再按本轮真实BOSS券价格计算可花金币。足以支付两张时仍可以批买2，不足两张但能买1时降为1；已持有的券不需要等待城墙/火箭/修包就绪才能使用。购买前保留背包容量、每天10次召唤、已管理至多两张、合法且不同出生点，以及买/用/返程耗时检查。未知过往购买历史或库存/反馈冲突仍不会无凭据追加。

首日补给及其它升级先扣`BossRaid.budget_reserve()`，只能使用剩余金币。开拓者在任务中不会被强制中断，但只要还有合法的首日购券行程，工人也不能在此期间花掉已足够的BOSS费用。收到buy后的实际背包变化，再确认库存并发use；双券分两个回合使用，不能预测购买/使用已成功。

`boss_raid.decision`日志输出实际金币、可花金币、当前券价、持券数、管理/部署数、缺墙数、购买关闭状态及原因，如`active_task/purchase_history_unknown/awaiting_inventory_feedback/purchasing_order/using_order`。`no_feasible_purchase_or_use`需结合钱、容量、时间和位置检查，不等价于已消费。

## 模块位置、接口与状态

| 位置/接口 | 参数及返回值 | 作用 |
|---|---|---|
| `app/config.py: Settings.build_cells(turn,kind)` | 当前Turn、`wall/rocket/gatling/railgun`；返回Pos元组 | 原蓝图/配置位置过滤到合法圈层 |
| `src/agent/gap_defense.py: WallGapDefense(strategy)` | 当前Strategy；共享Turn/ActionPlan/GameMemory | 只根据真实占位建立缺口事件 |
| `choose_responders()` | 无返回值 | 固定工人、imp及优先缺口；夜间不因原工人死亡把另一工人调回来 |
| `worker(role) / imp(role)` | 当前Unit；bool表示本轮是否接管 | 白天施工准备、入夜守缺口、待命与真实死亡后的接替 |
| `enter_gap(role)` | 当前Unit；bool | 只允许当前工人或已接替的imp在夜间解除所守墙位的路径预留 |
| `other_walls_ready()` | bool | 三炮及非事件缺墙实际建齐，不意味着物理封闭 |
| `posts(gap=None) / move_or_hold(role,goals,kind)` | 缺口、角色、目标集合、任务名 | 实际内侧邻格；共享下一步预约，不能走进现有占用 |
| `src/agent/brain.py` | `gap_guard`先于FirstNightDefense/BossRaid/RaidScouts构造 | imp缺口岗先于侦察/毁矿；工人缺口岗先于补给/采矿/避险 |
| `app/service/memory.py: wall_gap_defense` | gaps/worker_id/imp_id/gap/posts/imp_status | 保存原墙缺口及固定接力身份，观察原墙建成后清理 |
| `src/agent/first_night_defense.py` | `construction_ready()`区别于`closed()` | 其它合法墙完成后可以准备补给；供给先保留BOSS预算 |
| `src/agent/boss_raid.py` | `day_available/available_gold/budget_reserve/proposal/pioneer` | 原买/用账本、数量降级与时间预算，移除封墙及首夜补给采购门槛 |
| `app/service/turn_service.py` | `gap_defense`及`defense_diagnostic`JSON日志 | 缺口、身份、存活、真实墙HP及补给；不输出虚构临墙状态 |

无新增官方字段、路由、依赖或新配置。`enable_boss_raid`仍控制BOSS采购/操控；`enable_first_night_defense`控制首日补给，不关闭新缺口接力。`first_night_repair_stock=5`是剩余资金下的目标，不能再阻止购券；维修阈值仍严格低于30%，返程余量`return_margin=4`，正常升级阶段及BOSS射程/攻炮手优先级不变。

验证覆盖合法圈层、禁止临墙、剩余墙施工、左右镜像、夜间占用、工人守位/治疗/相邻修理、死亡与缺报后的imp接替、复活/补墙/退出、BOSS足额单买/双买、任务中的预算保护、收到库存后use及防守/观察分工。[验证报告](../../reports/VALIDATION-v1.2.6.md)区分本地输入与官方对局；本轮未运行新的官方比赛。
