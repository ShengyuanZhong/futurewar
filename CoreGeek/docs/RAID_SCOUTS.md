## 依据与问题

用户提供的`temp/boss_log1.log`与`temp/boss_log2.log`是当前版本的实战行为证据。log1有可见工人时可进行攻击；log2的本方BOSS30035在第一夜R71–103的观测中，炮台和可见英雄列表持续为空，策略只能转入攻击全局可见基地。接近基地本身没有让隐藏操炮者进入观测。

用户转述工作人员补充：**召唤机器人不提供视野，且移动和攻击不能在同一回合同时进行**。这与[v2.0任务书](../../32_docs/任务书.md)§4.3的常规单位/建筑视距4、全队共享及机器人全图可见区分开来：能看见机器人，不等于该机器人能揭开周围敌方角色。本次用活的捣乱鬼和工人提供观察来源，不在本地伪造敌角色。

log2还记录了多次基地攻击被判非法、换站位后才合法的现象；log1中距离3攻击工人可以合法，因此不能据此统一将机器人射程改成1。多格基地、其它建筑及擦角等弹道疑点仍待核准，不通过这次视野协作推测改写官方规则。正式源码不读取`temp/`，日志中的任务脚本也不在选手主机执行。

## 第一天分工

捣乱鬼第一天优先去敌基地后方上侧观察，不再由原毁矿任务把它拉走。第一夜观察任务有效时继续提供视野；任务结束后由原毁矿策略接管。

工人优先完成己方防御建设。只有下面条件同时成立，才分配一名固定的侦察工人：

1. 第一天白天、BOSS策略启用、敌基地位置可确定。
2. 真实观测中至少三座本方武器存活，永久墙规划集合非空，所有规划永久墙都已实际存在；需要建造或补齐的临时围挡也全部存在。
3. 至少两名活工人；排除已指定的占墙位防御负责人。
4. 观察点可达，按当时真实路线计算的步数不超过剩余白天回合。

墙是否齐全每轮重新检查，不使用“曾经建成过”的`opening_complete`缓存。发出最后一条建墙指令不算当轮已经建齐，要等后续观测确认。如果墙建齐太晚、道路被堵或观察点无法及时到达，不派工人，继续正常施工、经济与防守；捣乱鬼可以独立执行观察任务。

可分配的工人按实际到站成本、ID排序，选定后保持身份，不每轮重新选最近的工人。另一名工人沿用原策略：占墙位防御优先，其余时间正常工作。不会把唯一存活工人再派出去，也不会在侦察工人死亡后临时改派剩下的防守工人。

## 观察点与左右镜像

优先读取真实敌`station`。缺失时，沿用2×2基地整体镜像后备：敌基地左上角为`(width-2-own_x, height-own_y)`。镜像规则和召唤地理来自`src/agent/summoning.py`，不会直接把2×2基地左上角当作单格镜像。

| 敌基地左上角B | 捣乱鬼偏好参考点 | 工人偏好参考点 |
|---|---|---|
| 左侧`(bx,by)` | `(bx-4,by+2)` | `(bx-4,by-2)` |
| 右侧`(bx,by)` | `(bx+5,by+2)` | `(bx+5,by-2)` |

这是关于基地中心的水平镜像，横向偏移为`dx→1-dx`。例如敌基地`(9,22)`时偏好参考点为`(5,24)/(5,20)`；敌基地`(30,10)`时为`(35,12)/(35,8)`。参考点在默认BOSS出生列的更后侧，上下分开，尽量避开出生点和朝基地前进的通道。它们只参与候选排序，**不是必选的实际站位**；覆盖更多观察格的点会优先于参考点。

log1实际敌基地`(30,10)`的炮台曾出现在`(29,11)/(29,8)`，位于预计后排模板之外。只覆盖后排三炮会漏掉这些前侧炮位，因此观察区域取下面三部分的并集，再排除基地占格和越界格：

- 基地主体周围6×6邻域：`x=bx-2..bx+3,y=by-3..by+2`，剔除基地4格。
- 预计后排三炮的八邻格：左侧炮模板`(bx-1,by+1/0/-1)`，右侧`(bx+2,by+1/0/-1)`。
- 本轮真实可见炮台的八邻格。前侧炮位进入共享观测后，也加入其周围可能操炮的区域。

6×6是本模块的观察启发式，**不是新增或变更建造区规则**。模板只引导观察点选择，不生成虚假的武器或操炮者实体，也不把预计格数当作真实可见敌人数量。

候选必须是当前可达空地，在敌基地后侧，并且捣乱鬼位于`y≥by+2`的上侧、工人位于`y≤by-2`的下侧，避免停在中间通道；纵向阈值超出地图时收缩到地图边缘。工人在白天还会过滤当前路线步数超过剩余白天的候选。硬排除默认两个BOSS出生点、本方待生成坐标、本次真实请求出生点、另一观察者预约目标及本轮移动预留；真实建筑、单位、矿石、NPC和任务点继续由原寻路与动作门禁处理。

符合这些条件的候选依次比较：

1. 视距4内可覆盖的预计观察格数量，越多越优先。
2. 站位的本地机器人风险，越低越优先。
3. 与上一轮观察目标是否相同，优先稳定目标。
4. 与对应首选位的距离、真实路线步数和固定坐标顺序。

在没有阻挡的示例中，更靠近基地的观察点可能覆盖更多前侧区域：敌基地`(9,22)`时可选`(8,24)/(8,20)`，这些格被实际炮台、角色或预约占用时可退到`(7,24)/(7,20)`等候选；敌基地`(30,10)`时可能选择`(32,12)/(32,8)`。实际结果由覆盖、风险、旧目标与可达性共同决定，不能仅从参考点坐标推定最终目标。

所有候选都继续受出生点、预约和可见占用排除。任一替代点不保证永远避开BOSS的每条未来射线。这里只做站位和预约协调，不新增未经确认的角色挡弹规则。自定义敌方炮阵、动态障碍、侦察者死亡或站位暂不可达，都可能降低实际观察效果；扩大观察邻域不意味着一定能看见任意布置的全部操炮者。

## 昼夜衔接与待命

第一夜沿用已分配的侦察身份和观察目标。工人站位调整限制在能够覆盖观察区域的候选中，再按风险排序，不调用普通工人全图远离机器人的逃跑分支。原路线风险估值仍参与实际行走，故障或敌方占路时不保证能按最初预算到位。

到站后明确待命，消耗本轮角色调度权，不继续走向旧矿点。捣乱鬼移动或到站时清理旧毁矿任务；工人通过原协作模块记录`raid_scout`任务。两者每轮仍至多一条动作，没有“先移动再执行另一动作”的复合指令。工人的既有携药治疗仍可优先执行；占墙位防御的优先级也高于工人侦察。

本轮角色移动不会在决策中提前创造下一帧视野。BOSS只使用本轮请求真实传入的`teamEnemy.roles`；观察者到位后，是否看到敌角色取决于后续判题器观测。角色HP、炮旁位置和死亡状态仍由原BOSS流程逐回合重查。

## 暂停与退出

- 第一天白天防御再次出现缺口时，侦察工人让出控制权给原施工/经济流程；身份保留，条件重新满足后可以恢复。
- 活工人不足两名，或侦察工人成为占墙位防御负责人时，不继续占用其正常防守调度。
- 第2天、BOSS策略关闭、敌基地已毁或首夜BOSS已经出现后从本方存活列表消失，结束观察任务，恢复imp毁矿和工人原策略。
- BOSS尚未在夜间出现、但已处于待生成/已部署状态时，保留观察任务等待实际生成；不能凭券消失直接创建本方机器人。

首夜BOSS消失后，`finished=true`退出标记持续至第一夜结束，不在下一回合因`deployed`旧状态重新启动；第2天或关闭策略后清除。此时只确认本方存活列表变化，不在日志中推定具体死亡原因。释放侦察角色任务也不意味着角色立刻回到己方基地，后续移动由原策略决定。

## 模块、函数与状态

| 位置/函数 | 参数与作用 |
|---|---|
| `src/agent/raid_scouts.py` `RaidScouts(strategy)` | 接收当前Strategy，确定敌基地与任务有效期，读取真实防御状态并选择固定工人身份 |
| 同上 `walls_ready()` | 检查非空永久墙规划、三座存活武器及无待建永久/临时墙 |
| 同上 `watch_cells()` | 合并基地主体6×6观察邻域、后排模板及真实可见炮台邻格，不改变建造规则或Turn中的敌方实体 |
| 同上 `preferred(role)` | Unit→该角色在当前敌基地侧别的偏好上/下参考点，覆盖优先排序可以选择其它目标 |
| 同上 `post(role)` | Unit→当前可达且符合预约、出生点和侧别条件的观察点；无法选择时为None |
| 同上 `observe_from(role)` | Unit→接管标志；移动一步或到位待命，记录观察任务与预计覆盖 |
| 同上 `imp(role)` / `worker(role)` / `is_worker(role)` | 原角色分支的接管入口及当前工人侦察资格检查；白天缺墙时不再保护其侦察待命，可恢复正常施工及协作 |
| 同上 `release(finished=False)` | 释放侦察任务，清理原协作模块中的`raid_scout`工人任务；finished为true时保留终止标记，避免首夜再次启动 |
| `src/agent/brain.py` | 构造观察调度；imp先尝试观察再毁矿，worker先处理占墙防御再观察，其余分支保持原顺序 |
| `app/service/memory.py` `GameMemory.raid_scouts` | 按队伍保存侦察身份、目标与生命周期 |
| `app/service/turn_service.py` | 输出`raid_scout`状态与这些角色本轮命令，原BOSS诊断继续输出 |

状态主要字段：`base/round/seen_boss/finished/walls_ready/worker_id/home_worker_id/worker_status/posts`。`posts`按角色ID记录`goal/status/round/steps/ready_by_night/coverage`，其中`status`为`travelling/holding/unreachable`；无法到达时部分估计字段可能不存在。`home_worker_id`记录未外派的工人身份，具体防守行为仍由原占点、施工和工人策略决定。

| `worker_status` | 解释 |
|---|---|
| `waiting_for_walls` | 三炮/非空完整永久墙/临时围挡条件尚未满足 |
| `not_enough_workers` | 未分配侦察身份时，活工人数不足两名 |
| `waiting_for_route` | 防御与人数条件已满足，仍等待可分配角色及路线条件 |
| `unreachable_or_too_late` | 当前候选没有可在剩余白天内到达的观察点 |
| `assigned` | 已固定侦察工人身份；是否已到位另看posts |
| `paused_for_walls_or_blockade` | 已分配工人因白天缺墙或占点防御职责暂停观察 |
| `home_defense` | 已分配身份但只剩不足两名活工人，保留原防守/经济调度 |

`coverage`表示观察点到预计观察格的切比雪夫距离≤4的格数，**不是实际可见敌角色数**；`ready_by_night`表示当前路径预算，不是将来到位的保证。真实可见角色、BOSS候选和动作反馈从原`robot_diagnostic`读取。

本次沿用`enable_boss_raid`控制整个首夜购买、操控与视野协作；`enable_robot_diagnostics`只控制两类机器人诊断输出，不改变观察策略。没有新增官方请求字段或运行依赖。

## 调试与验证边界

`raid_scout round=... state=... commands=...`是INFO日志，查看固定角色ID、观察目标、状态、剩余步数与本轮移动命令。与同回合`worker_motion/imp_motion/robot_observation/robot_diagnostic`关联，可以区分工人尚未获准离家、观察点被占、单位到站待命以及本轮仍没有真实敌角色视野。

本地检查应覆盖左右镜像、前夜路线预算、缺墙/三炮/临时墙条件、占点防御优先、身份稳定、双目标与出生点预约、首夜持续待命、死亡与第2天恢复，以及BOSS消失后连续回合不重启。合成视野样例只能验证策略如何使用传入的可见信息，不能证明实际判题器一定显示相同敌单位，也不能用全图敌方角色列表冒充真实受限视野。

实际执行结果见[v1.2.3验证报告](../../reports/VALIDATION-v1.2.3.md)。本次解决观察来源与角色分工，官方对局中的可见性、存活、伤害和弹道结算仍需真实日志验证。
