## 通行与施工

未建墙是可通行空地。`movement_reserved(role)` 保留三格炮位、实际已发动作的预留位置、本轮明确施工目标，以及上一帧仍有活工人和材料支持的施工目标；对工人额外保留操炮位。真实墙、基地、矿点及角色的占用仍由 `Turn.blocked()` 处理。

工人可以穿过未建墙位，但 `WorkerCoordinator.move_to(..., kind='build:...')` 不把其他预建位选作最终施工站位。`clear_build_cell()` 只对炮位、操炮位和具体施工需求让位；经过一格尚未预约的墙位不会被下一轮强行驱回，避免旧的两格往返问题重新出现。缺口候补捣乱鬼仍不能在主工人存活时穿过缺口，只有真实接替条件成立才入位。

前三炮继续占用初始75金币；观测确认三炮后才造墙。不能参与当前建炮动作的工人先采石，不再挂机。门负责人的一块封口石、白天入口与夜前封回17墙不变。

## 任务行程与购券

首日仍按 `TASK_SEQUENCE=(1,2,1)` 尝试，任务2的两格范围和30回合冷却不变。活跃任务继续由用户提供的控制器和 prompt 执行，本次没有改题目处理逻辑。

领取前使用实际路径，估算 `max(到任务点路程, 冷却) + 任务官方时限 + 后续行程`。第三次任务还预留商店采购、逐张使用召唤令、回操炮位和 `return_margin`。这里使用完整任务时限，是保守调度预算；预算不足不等于题目事实上绝不可能更快完成。

若点位永久不可领（`isValid=False` 且没有冷却）、没有该任务点，或剩余任务的完整预算不足，则设置 `task_schedule.itinerary_closed=True`，记录关闭回合、原因及未尝试的步骤。同回合重新评估 BOSS 采购，以已经确认的成功次数冻结0～3张目标。关闭行程不向 `task_attempts` 写入虚构的结束或成功事件；金币余额不会被当成任务成功。

临时找不到去程、操炮位或回程时，记录 `route_blocked`，不会把10000当路程或永久关闭行程。任务尚在执行、合法领取后等待题目出现，或第三次仍可完成时，都继续原任务顺序，不提前购券。实际购物仍要求金币、背包、合法出生点、使用回合及回防预算满足；若关闭时已太晚，也不能发超时购券动作。因此这次修复的重点是尽早出发和提前保护采购窗口。

`BossRaid.shop_trip(role, use_count=1, start=None)` 的 `start` 用于预测任务完成后的商店行程；`None` 表示当前角色的实际购物。缓存分别记录这两种模式，预测结果不能授权已经过期的实际采购。

## 捣乱鬼侦查与炮位记忆

敌方基地和城墙全局可见不代表已看见炮台或炮手。基地炮环必须实际进入普通己方单位的4格共享视野，或真实确认三处武器位置。机器人始终不作为视野来源。

`GameMemory.enemy_weapon_sites: dict[Pos,str]` 保存实际见过的炮位与类型；根据用户补充，武器不能主动拆除，这些位置长期用于判断阵型。该记录与 `enemy_structures` 分离：已毁炮台可以保留历史位置，但不会变成攻击目标或阻挡弹道的虚假建筑；重新看见重建炮台时更新真实ID和类型。`enemy_layout_ready(..., confirmed_sites=())` 和召唤选点接收这一独立历史集合。

捣乱鬼安全在场且当前视野覆盖操炮位时，可以满足召唤观察员条件，避免等工人走完重复路线。工人仍在墙构造完成后派出并持续提供视野，家防工人和缺口候补不被挪作侦察。捣乱鬼路线留出抓捕缓冲；若对方逼近导致已在危险区，则先向更远位置脱离，恢复安全距离后继续侦察。无法安全探明的区域不会用猜测补成视野。

## 开发与诊断入口

| 文件/函数/字段 | 参数及作用 |
|---|---|
| `src/agent/brain.py: movement_reserved(role=None)` | 返回实际动作、炮位和施工预约；不预留整圈空墙 |
| `clear_build_cell(role)` | 有具体施工需要才移开墙位占用者；避免采矿路线反转 |
| `opening_worker(role)` | 先建炮；无法参与时并行采石；造墙仍等三炮观测确认 |
| `task(role)` | 1→2→1、真实路径/冷却预算、临时阻塞等待及明确关闭行程 |
| `task_schedule.itinerary_closed / close_reason / unattempted_steps` | 行程关闭标志、原因和未做步骤；与真实尝试账本分离 |
| `BossRaid.tasks_finished()` | 三次真实结束或明确关闭行程才进入购券；仍要求没有活跃题目 |
| `BossRaid.shop_trip(role,use_count=1,start=None)` | 商店、采购一回合、逐张用券、回防和余量的总预算；预测和实际缓存隔离 |
| `raid_scouts.py: refresh_readiness()` | 工人或安全捣乱鬼的当前视野；墙构造和真实布局继续作为准入条件 |
| `memory.py: enemy_weapon_sites` | `Pos→武器类型`，只保存实际确认过的位置，独立于存活/遮挡记录 |
| `robot_raider.py: observe_structures()` | 记录实际炮位；不推测移动单位，也不拿历史阵型攻击 |

`first_day_policy` 新增开拓者位置/实际指令、任务点 `valid/cooldown/timeout` 和行程关闭标志；`task_schedule` 记录去程、回程、尾程、所需轮数及白天剩余轮数。`raid_survey` 新增 `weapon_sites/imp_ready/observer_ids`，可区分“已知阵型”“当前视野”和“工人仍在路上”。
