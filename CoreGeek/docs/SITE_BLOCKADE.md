# 敌方占点与临时绕建城墙

v1.1.3，2026-10-09。在v1.1.2上增加敌方恶意占点的防御，不改变三火箭开局、永久U形墙、升级阶段、火箭选点、正常工人经济和任务流程。使用现有 `build/remove/collect/move/use`，没有新增HTTP字段或路由。

## 识别与处理流程

同一个存活敌方角色（worker/pioneer/imp），在同一个尚未建造的己方规划设施位置，连续观测**超过5回合**才判定占点，即第6次连续观测触发。单位ID或位置变化、缺报、死亡、不可见都会断开计数；重复同一回合不会累加，HTTP重复请求沿用原缓存。机器人及敌方建筑不按角色占点计数。

所有规划墙位和缺炮位均可记录占用；本版绕建和待命仅用于城墙缺口。确认的缺墙位置会保留到原墙在后续观测中确实建成，不会因为敌人离开或一条build命令已经发出就认为防御恢复。

1. **白天绕建**：对确认的墙位，在原U形墙外侧突出一格形成临时围挡；直边通常3块，外角通常5块，相邻缺口共享临时墙。复用两个工人的石头配额、独立施工目标和让行机制，保留三火箭先造的开局顺序。
2. **携石待命**：临近夜晚选一名可到达内侧邻格的工人，至少保留一块石头。优先沿用现有负责人，其次考虑实有石头、维修职责和路程；空包时把采一次石头与返程计入提前量。另一名工人继续原来的经济或维修策略。
3. **夜间守候**：工人在原缺口的内侧邻格等待，不被普通让行或采矿重新派走；可以原地修复相邻危墙，仍严格低于30%才用包。临时围挡在敌人离开后继续封住外侧通路。
4. **白天抢补**：工人能看到原位置为空、相邻、有石头、不会封死原出口时，优先发出原墙的build。原位置若被敌人重新占据或补建失败，保留临时墙，继续观察和下一次补建。
5. **确认后拆临时墙**：必须在下一份观测看到原墙实际存活后才拆。只拆本进程曾安排建造、且已不再支持其他缺口的临时墙；预先存在于同坐标的墙不自动归为临时墙。两工人拆墙目标分开并保留行程目标。

文档《32_docs/任务书.md》§4.4仍明确规定build仅白天可用，故夜间不发build。用户实战反馈“占点者夜间第一回合离开”用于安排守候，但不作为必然发生的规则；第2天首轮位置可见且空闲时立即尝试补建，随后才拆围挡。不能保证在双方同时行动时，任何抢位都必胜。

## 外侧围挡示例与建造区域

左侧基地(6,7)，原墙缺口(9,7)，另外11块原墙已经在位时：

```text
          x=8   x=9   x=10
y=8        .     W      T
y=7        工    敌     T
y=6        .     W      T

W=原墙，T=临时墙；工人待在原缺口内侧一格，可直接补(9,7)。
敌人离开后，先建原墙，再按真实观测拆T。
```

正面直边取外侧三个邻格；顶部取上侧三个邻格；底部取下侧三个邻格；正面与上下边的外角取两组并集，合计五格。右侧基地按实际基地位置镜像，后排火箭/P和内侧维修通路不改成临时墙位。生成时过滤地图外、基地格和非空地中立格；本轮占用、施工目标争抢和出口检查仍由原规则限制。

默认 `allow_base_surroundings=true` 延续用户此前“基地周围可建造”的授权假设，临时围挡将其扩大到原U形墙外侧一格。**这不是已核验的官方黄色建造区坐标**，仍属于D01；需在官方对局核对这些额外格是否允许建墙。显式verified布局和strict模式不会被扩大，无法生成围挡时仍保留占点记录和备石守候。原 `Settings.build_cells` 仍是永久布局，不把临时墙当成永久升级目标。

## 模块、函数与参数

| 位置/函数 | 参数、返回与作用 |
|---|---|
| `src/agent/site_blockade.py` `SiteBlockade(strategy)` | 当前Strategy；更新占点与围挡状态，供当轮工人调度使用 |
| 同上 `observe_sites()` | 连续回合、敌方ID、当前位置与规划设施；更新计数并保留未修复缺口 |
| 同上 `choose_watcher()` | 当前工人、背包、诊断路线和剩余白天；稳定选择负责人和待命时机 |
| 同上 `posts(gap)` | 原墙坐标Pos→内侧相邻站位集合 |
| 同上 `watch(role)` | Unit→bool；抢补原墙、筹备石头、原地危墙维修或待命，True表示该工人本轮由占点防御接管 |
| 同上 `cleanup(role)` | Unit→bool；白天拆除已不需要的本方临时墙或行走到相邻格 |
| 同上 `is_waiting(role)` | Unit→bool；让行模块保护已到位的负责人 |
| `app/config.py` `Settings.wall_detour_cells(turn,gap)` | 当前观测和原规划墙位→临时围挡坐标；只对默认U形布局及授权fallback生成 |
| `actions.py` `ActionPlan.authorize_wall_detour(gap)` | 按上述几何登记本轮临时建墙候选；不能放宽夜间、材料、占用或距离校验 |
| `brain.py` `construction_walls()` | 永久缺墙+待建临时墙；供石头配额、施工、寻路预留与建筑位清理共同使用 |
| 同上 `run_worker(role)` | 占点待命优先于普通让行/经济；白天确认原墙后可拆临时墙，其余流程沿用 |
| `upgrade_policy.py` | 阶段与完成判断排除已登记临时墙，避免为即将拆掉的墙买券/升级 |

`GameMemory`新增进程内状态：

| 字段 | 含义 |
|---|---|
| `site_occupations[Pos]` | `enemy_id/count/last_round`，只存本轮可见且在未建造设施上的存活敌方角色 |
| `wall_blockades[Pos]` | `enemy_id/confirmed_round`，确认的缺墙位置，原墙实际建成后清除 |
| `temporary_wall_sites` | 本进程为绕建发过build命令的坐标集合；不将未观测到的build成功当事实 |
| `blockade_worker_id` | 备石与待命负责人；死亡/不可达后重新选人，复活者不抢现任岗位 |
| `blockade_watch` | 夜前准备和夜间等待状态，可跨昼夜；不因仅发出build而提前结束 |

待命提前量至少10个白天回合，或“到岗步数+return_margin”“采一次石头与返程估计+return_margin”中的较大者。`return_margin`仍为已有配置，默认4。返程估计使用距离，不保证拥堵地图的最坏到岗时间；石矿不存在、包满且不能出售、岗位不可达或工人被击杀时，无法凭空补充石头。

服务新增 `wall_blockade` 摘要日志，包含回合、计数、缺口、临时墙、负责人和待命状态。原 `worker_jobs/worker_motion` 保留，新增任务名 `blockade_watch/blockade_repair`；进程重启会重新累计占点次数，也不会自动拆除无法证明属于本进程的既有墙。

## 本地验证

`tests/test_site_blockade.py`覆盖16项：第5/6回合阈值、重复/断报/换ID、离开后缺口保留、角色类型/死亡、直边/外角/镜像、建墙白天和区域门禁、两侧完整围挡与天亮补建/清理、另一工人采矿、失败/重新占回、临时墙不升级、共享围挡、原地危墙维修、负责人死亡/复活、空包备石返岗、既有墙不误拆及HTTP缓存幂等。

多回合用例是独立合成观测夹具，逐条核对实有石头、八方向相邻、已占用目标和同轮目标冲突；不是官方机器人移动或抢位结算模拟器。完整结果见[v1.1.3验证报告](../../reports/VALIDATION-v1.1.3.md)。
