# 捣乱鬼策略与维护

v1.2.3首日新增[敌后视野协作](RAID_SCOUTS.md)，优先为BOSS提供共享视野；首夜任务退出及第二天起恢复下述毁矿策略。关闭enable_boss_raid也恢复原毁矿策略。

v1.1.0，2026-10-09。依据用户指令及 `32_docs/任务书.md` §4.1、§4.4、§4.5.2 和 `32_docs/接口文档.md` §1.3.1、§2.3，加入 `imp` 的移动和破坏策略。原工人经济、建筑升级、开拓者操炮/任务模块保留。

## 行为与半区

捣乱鬼在所有昼夜阶段选择对方半区的石/铁/铜矿，走到矿点邻格后每轮执行 `destroy`。文档要求连续4回合，每个回合必须发送破坏动作；停顿、移动、死亡/抓捕或矿石被采光会打断。本项目不自行结算矿石消失、10回合刷新抑制或复活，全部以之后的官方观测为准。

半区按文档“左下至右上”定义为 `(0,0)` 到 `(width-1,height-1)` 的对角线。矿点 `(x,y)` 的侧值为 `y*(width-1)-x*(height-1)`：正数是上侧，负数是下侧。己方基地输入是2×2左上角，用基地中心 `(base.x+0.5,base.y-0.5)` 所在侧确定己方，对侧才是破坏目标；不按challenger/defender写死位置，支持换边。正文未规定线上的矿归属，当前本地策略跳过侧值为0的矿，避免误毁己方矿。

目标优先级为：继续当前有效、可达的敌方矿点 → 选择步数最少的可达敌方矿点，同成本按坐标。步行途中也保持目标与合法站位，避免看到新矿就折返。邻格执行破坏时不移动，四轮之后只要观测中矿点仍存在就继续发送，不能仅凭本地次数认为已经成功。矿点消失、类型不再是矿或路线不可达时重新选择。无敌方可达矿点时等待下一轮新观测，不改去破坏己方矿。

按用户要求不逃避机器人、不黄昏回防、不治伤、不采购，不受工人维修分工或开拓者任务暂停影响。路线不使用工人的危险权重，允许经过机器人威胁范围；实际机器人占用格、建筑、矿、NPC和角色仍是移动障碍，同轮目的格预留也仍有效。“不躲机器人”不等于可以穿越其实体格。

## 复活与状态

`Turn.imps()`只返回当前HP>0的捣乱鬼，动作使用输入的真实ID，不固定为10014/20014。死亡或单位缺失后清理该角色任务；次日第一回合只要官方报告角色已复活，就重新选择目标并立即移动/破坏，不等待晚上，也不由客户端虚构复活时刻。

即使漏收死亡报文，连续观测中角色发生超过一步的位移，或原地破坏期间位置改变，也会丢弃旧任务重新规划。基地消失时保留同局已知的己方半区；没有己方基地但能看到敌方基地时取其反侧。若初次观测两方基地都不可用且没有半区记忆，则暂不破坏未知归属的矿。

`GameMemory`新增字段：

| 字段 | 作用 |
|---|---|
| `imp_home_side` | -1/0/1：己方基地所在对角线侧，0表示尚未知；换日保留，换队/重开局隔离 |
| `imp_tasks[unit_id]` | 每只存活捣乱鬼的kind、target、goal、position、round、issued_streak；保持最近连续回合任务 |
| `issued_streak` | 本地连续发出的destroy数，日志显示上限4；明确失败反馈时重计。不是官方破坏进度，不用于删除矿或停止动作 |

`TurnService`增加 `imp_motion` 日志，含半区、任务/站位与实际响应动作。原 `worker_motion` 只记录工人，捣乱鬼不进入工人的让行、避敌、背包、备货或维修状态。

## 模块、函数与参数

| 位置/函数 | 参数与结果 |
|---|---|
| `src/agent/protocol.py` `IMP` / `CONTROLLABLE_TYPES` | 新增imp可控角色；`Turn.imps()`返回存活imp元组 |
| 同上 `destroy_command(pos)` | `Pos`→`{"action":"destroy","targetPos":[...]}` |
| `src/agent/actions.py` `ActionPlan.add` | 新增destroy校验：仅imp、单坐标、矿石八邻域、本轮未行动；昼夜均可用 |
| `src/agent/map_regions.py` `diagonal_side(pos,width,height)` / `base_side(turn)` | 与三级火箭共享；返回半区侧值，不使用浮点边界判断；imp_policy保留导入兼容 |
| 同上 `ImpController(strategy)` | 根据基地确定半区，清理死亡、跳轮和复活前旧任务 |
| 同上 `decide(role)` | 当前imp `Unit`→是否已安排动作；在ActionPlan写入move或destroy并保存任务 |
| `src/agent/brain.py` `Strategy.run()` | 开拓者先安排、捣乱鬼独立安排，再逐工人调度；imp分支在治疗/工人逻辑之前 |

敌方半区限制属于用户策略，`destroy`动作本身的官方校验不禁止其它半区，因此手动构造合法的同半区destroy仍可通过动作校验；正式策略仅选择对方半区。

本次不依赖 `temp/`、不调用LLM，不新增HTTP字段、路由或配置。复赛的catch、小车、可控机器人、remain和其它参数变更仍按[复赛规则索引](ROUND_OF_32_RULES.md)分别接入，不将本次实现描述为完整v2.0兼容。
