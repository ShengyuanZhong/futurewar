# v1.2.24 侧翼侦察、同侧召唤与共同目标

本次调整属于策略优化：捣乱鬼初次前往敌基地时优先从上侧或下侧绕行；同批BOSS从同一侧召唤，尽量集中攻击共同目标。规则参照 `32_docs/任务书.md` §4.3、§4.4、§4.5.4、§4.6、§4.7 与 `32_docs/接口文档.md` §1.5、§2.2：共享视野四格、八方向移动、每单位一动作、合法召唤坐标和真实动作反馈继续执行。机器人无视野、不能同轮移动并攻击、射程三及45°弹道继续采用用户已确认的补充信息。官方和temp原件不改，运行时不依赖temp。

## 捣乱鬼的初次侦察路线

入口仍是 `RaidScouts.opening_imp()`，在实际完成初次阵型侦察前优先于回家补位或毁矿。新增 `scout_flank.flank_step()` 分三段行走：

1. `outbound`：先向选定的上侧或下侧入口移动，使用入口左右各两格的纵向通道。
2. `crossing`：沿横向侧翼通道接近敌基地，通道限制在目标行上下各一格。八向BFS不能借同成本斜线切回地图中部。
3. `approach`：沿敌基地一侧的纵向区域靠近实际侦察站位，继续检查可见抓捕者；拿到炮位知识或实际到站后结束绕行。

上下两条候选行分别由出发位置与敌基地的较低/较高纵坐标向外偏移五格，并限制在地图内的第1至倒数第2行。入口和横穿终点允许左右一格内选择实际可达位置。按实际入口路径加两段距离估算总路程，再以第一段距离打破平手；选定后保存侧向、入口、横穿终点及阶段，普通回合不反复切换。基地改变时丢弃旧计划。

每段路径都复用 `scout_route()`：实际建筑、矿点、NPC、其它单位、已预约召唤位和攻击通道仍不可穿越；当前可见敌方可控角色周围两格继续禁入。已经被敌人贴近时保留原先逐步拉开距离的出口处理。一个敌人暂时不可见，不会在地图上凭空变成障碍或抓捕者。

已经在敌基地占地八格以内的迟到观测不重新走全图绕行。三炮已确认或真实侦察完成后，直接转入原观察/回防/毁矿分工。某段实际不可达时记 `fallback` 并结束该次绕行计划，恢复原安全路线或原逃离处理，不在绕行入口和原路线间反复折返。侧翼是降低未知抓捕风险的偏好，不代表隐藏敌人不会接近，也不保证任何地图都更快。

## 同批BOSS从同一侧部署

`spawn_side(pos, base)` 用真实2×2基地中心判断 `north/south/east/west`，支持镜像；不能只拿基地左上角当中心。`BossRaid.spawn_positions()` 在实际侦察选点时保存 `group_spawn`：

```text
base: Pos       # 当前敌基地，防止跨基地使用旧计划
side: str       # 同批固定方向
anchor: Pos     # 首次选定的合法召唤点
```

后续逐张用券、实际失败位置重选均沿用这一侧。普通阵型优先选择锚点两格内的合法位置；没有近点时仍保持同侧，在合法候选内选择其它点。重复预约、实际失败点、建筑、NPC、建造区等限制保留，数量仍由三次任务实际成功数决定，不因新策略增加券数。

炮手受墙保护时继续使用v1.2.21共同墙计划，`plan_assault()` 追加 `preferred_side` 并约束出生点确实属于该侧，避免角点的侧向分类偏离。其它阵型的 `scouted_spawn_candidates()` / `scouted_spawn_position()` 增加 `preferred_side` 和 `anchor`；独立调用时也会从已有pending位置继承方向。当前侧找不到合法方案时返回空结果，不跨侧凑数或伪造召唤成功。实际旁移后的机器人站位仍以夜间输入为准。

## 共同选敌与攻击

既有“占住最佳操炮位且全队可直射基地→全队攻基地”和“共同墙→真实破口→基地”仍优先。其它阵型有两只以上存活、可行动BOSS时，`shared_controller()` 在本轮当前可见的合格炮手中选一个共同目标：

1. 优先当前有更多BOSS能合法直接命中的人员。
2. 同样的参与数量下，优先继续攻击上轮共同目标，减少因回血或另一个残血角色出现而反复换人。
3. 再比较按当前可参与伤害估计的攻击轮数、实际HP、全队距离和ID。

三火箭阵型仍仅把共同三炮位上的可控角色作为合格人员，其它阵型沿用武器周围的工人/开拓者范围。单只BOSS保留原选敌规则。当前死亡、失视或离开合格位置的人员不再参与选择；记忆里的ID/坐标只用于偏好比较，不提供隐藏攻击权限。每台机器人仍单独核对当前射程、遮挡、失败射线与可达站位，不能射中时尝试靠近共同目标。追击不可达或超预算时保留攻基地回退，物理条件不允许时不能保证每台都同时打同一人。

没有人员目标、全队当前都不能直射基地，且没有BOSS能在三步以内走到基地直射位时，`shared_obstruction()` 可选择当前真实可见的共同挡路墙/武器。优先更多BOSS能射中的同一设施，能打者攻击，不能打者尝试靠近；存在更短的基地射击路线时继续进位，不为统一目标无谓拆墙。前排已经有基地射线时保留既有进位与攻基地策略。

共同目标选择每回合重查，不扣减真实HP来预测击杀。即使本轮第一发足以击杀，也不会在尚未结算时让后调度BOSS改打别的人员或墙。基地不同占地格共享同一建筑血量，向不同占地格攻击仍属于集火同一基地。

## 函数与状态位置

| 文件/入口 | 参数与结果 | 作用 |
|---|---|---|
| `src/agent/scout_flank.py` `flank_step(scouts, role, post)` | 当前侦察控制器、imp、真实候选观察位 → `Pos`或`None` | 返回绕行下一步；None交回原路线，不直接发送动作。 |
| `src/agent/raid_scouts.py` `scout_route(role, ignore_workers=frozenset(), allowed=None)` | 当前角色、仅诊断用途的忽略集合、可选允许区域 → `Routes` | 各阶段限制通道，仍保留原抓捕禁区、障碍及预留。 |
| `src/agent/summoning.py` `spawn_side(pos, base)` | 两个Pos → 四方向字符串 | 按2×2基地中心分类。 |
| 同上 `scouted_spawn_candidates/position(..., preferred_side=None, anchor=None)` | 原参数加固定侧与可选锚点 → 候选元组/单Pos | 复用真实阵型与合法性，普通出生点不再独立换侧。 |
| `src/agent/wall_assault.py` `plan_assault(..., preferred_wall=None, preferred_side=None)` | 原共同墙参数加固定侧 → 计划或None | 同墙突破继续满足同侧约束。 |
| `src/agent/robot_raider.py` `shared_controller(operators)` | 当前合格人员 → 当前Unit或None | 本轮全队共同人员目标。 |
| 同上 `group_shot(robot,target)` | 真实机器人、当前Unit → bool | 检查射线、范围和实际失败反馈。 |
| 同上 `shared_obstruction(robot,route,base)` | 当前机器人/路线/敌基地 → 是否已安排动作 | 需要拆障时尽量集中同一设施，保留短路直攻基地。 |

`GameMemory.raid_scouts['imp_flanks'][imp_id]` 保存路线阶段，`raid_survey` 日志包含它。`GameMemory.boss_raid['group_spawn']` 保存方向/锚点；`group_focus` 保存本轮目标ID/坐标/类型/回合，由 `first_day_policy` 和各 `robot_diagnostic.group_focus` 输出。检查日志时应核对目标记录的round，不把旧偏好记录当成本轮仍可见的目标。

首日开拓者仍须三次尝试实际结束后才能抓捕，工人即时抓捕及建家、分矿、车辆侦察等基线保持。本轮验证范围、实际数量、源码哈希和局限见[首日验证报告](../../reports/VALIDATION-v1.2.24.md)，本地合成输入不代表官方对局成绩。
