# v1.2.21 多 BOSS 集中破墙与基地攻击

本版调整第一天的召唤选点和第一夜 BOSS 攻击：敌炮手或最佳操炮位必须拆墙才能攻击时，放弃为清理炮手消耗火力，改从不同侧集中突破同一堵墙，破口形成后攻击基地。另一项更高优先级是：最佳操炮位已由本方 BOSS 占住，而且全部存活 BOSS 当前都能直接攻击基地时，全队持续攻击基地，不因敌方角色出现而换目标。

这是用户指定的策略优化。规则依据为 [v2.0 任务书](../../32_docs/任务书.md) §4.3、§4.5.4、§4.6.1、§4.7，以及 [v2.0 接口文档](../../32_docs/接口文档.md) §1.3–1.5、§2.1–2.2。BOSS 不提供视野、不能同轮移动并攻击、射程为切比雪夫距离三、恰好 45°攻击只检查对角线格的补充说明沿用用户已向比赛工作人员确认的信息。官方文档、样例和 temp 原件均保持原样，正式源码不依赖 temp。

## 本次两张图表达的阵型

用户第一张示意图中，敌基地在左上区域，最佳操炮位在基地南侧且被围墙保护。三只 BOSS 应从北侧围墙外召唤，集中攻击一堵北墙，随后调整至能直射基地的位置，避免为击杀南侧操炮手浪费多轮伤害。

第二张图中，最佳操炮位在基地西侧，北侧与西侧炮台组成保护布局。BOSS 从南侧墙外集中破口。它说明“不同侧”需要根据真实炮台阵型、墙体和可用射线选择，不能把所有左上基地固定为北侧出生。右下基地使用实际坐标计算相应选择；不假设双方地图、商店和矿位完全镜像。

图中一列机器人是示意。实际三个出生点仍需分别在地图内、双方建造区之外，避开 NPC、已预约召唤点和真实固定障碍。动态占用可能导致官方旁移，第一夜必须从真实出生位置重新规划，不把白天选好的格子当作实际站位。

## 保护炮手的判断

规划使用当前全局可见墙体、敌基地占地、真实观测后保存的炮位及类型，以及当前可见人员。最佳操炮位根据已确认炮位计算最大共同控制数量；三火箭模式仍使用共同三炮位。缓存炮位支持几何分析，不创建敌角色、ID、血量或视野。所有最佳操炮位均受保护，或者任一合格当前可见炮手受保护时启用该模式。三火箭人员范围继续与共同三炮位限定保持一致。

“受墙保护”同时检查射线和静态可达性：从合法外侧空地按八方向搜索，不穿越实际墙、基地、已确认炮位或NPC；若能经开放入口走到射程三内、无墙且无遮挡的射击格，就不需要破墙。没有这种射击格、但存在去掉墙即可射到目标的外侧射线时，才判为墙保护。动态角色占门不会被当作永久封墙。只因武器或基地挡线、角色暂时失视或超过射程，不等于炮手受墙保护。恰好 45°射线旁边两堵墙不参与遮挡，不能因此误启破墙策略。

若当前看不到炮手，仍可对已确认的最佳操炮位做几何判断。这里的操炮位是布局假设，只用于选择出生方向与共同破墙目标；机器人不能向推定有人或旧角色位置发人员攻击。

保护判定成立后，规划记录一面墙上的共同目标，不再让每只 BOSS 各找一堵墙或为了炮手绕向另一侧。有效旧目标保持稳定，实际墙体、炮阵或可用召唤点变化时重新核验。

## 召唤与夜间协作

白天采购数量仍由开拓者按任务二→任务一→任务二的三次尝试结果决定，成功数决定零至三张。采购工仍在三次尝试后按实际价格和库存买券、逐张用券；个人建墙交接、购物截止、首日分矿及捣乱鬼首次侦察保持 v1.2.20 基线。

保护模式中的多个用券动作共享同一进攻侧、同一目标墙和预定出生集合。每次用券继续检查实际库存、合法位置、此前成功预约和失败位置；反馈未确认成功时不提前增加已部署数。失去炮手当前视野不使已确认炮阵变未知，也不单独阻止召唤。

夜间每只 BOSS 依据实际位置、存活状态、当前全局墙体和动作反馈执行：

1. 优先检查全队基地攻击条件，满足时分别向有清晰射线的基地占地发攻击。
2. 保护模式尚有共同目标墙时，能射中该墙的 BOSS 原地攻击；不能射中者寻找可达、射程三以内且弹道清晰的站位，只发移动。
3. 目标墙被本轮真实观测确认不存在或死亡后，转向基地，不因预测本轮总伤害足够而让后调度机器人提前穿墙。
4. 部分 BOSS 尚未进入基地射程时，已有射线者可在保留射线的前提下继续向破口内推进，为队尾腾出射击空间。所有存活 BOSS 当前都能射基地后，停止进位并集中射击；没有可执行进位时，已有射线者先攻击，其余等待真实腾位或寻找合法射击格。不能同时移动攻击，也不假设同伴已腾空。
5. 出生旁移、移动失败或攻击失败使用下一轮实际位置及平台反馈纠正。计划站位和伤害估计不能代替真实反馈。

目标墙被敌方重建、场景变化或旧计划不可用时重新检查目标。没有合法不同侧召唤方案时不伪造出生点；已出生机器人没有共同破墙计划时仅走基地攻击分支，不转去追受保护人员。射线和墙体死亡均依据实际观测。集中突破不增加召唤权限，也不让 BOSS 获得隐藏角色视野。

## 基地集火优先条件

`RobotRaider.group_base_ready()` 要求：至少一只存活本方 BOSS 实际占住已确认最佳操炮位，而且每只存活本方 BOSS 当前都能从自己的真实位置合法直射敌基地。不是“走几步以后可打”、不是同伴本轮计划进位，也不是只检查前排。

条件成立时，即使最佳位旁、其它炮旁或基地旁出现工人、开拓者或捣乱鬼，全部 BOSS 都继续攻基地。条件不成立时，保护模式仍按共同破墙计划；其它阵型和未保护场景继续执行 v1.2.19 人员资格与 v1.2.14 进位逻辑。死亡、眩晕、真实攻击失败和基地不存在等条件仍正常处理。

`count` 是本次仍需安排的出生数，必须大于零；`pending` 是已成功预约的位置，`failed` 是实际失败后排除的位置。`preferred_wall` 可为墙的 `Pos`、实际墙 ID 或墙对象，用来保持后续用券与先前同墙目标一致。返回计划包括 `wall_pos: Pos`、`wall_id: int`、`side`（`north/south/east/west`）、`spawns: list[Pos]` 和敌基地 `base_cells`。候选侧排除炮手 / 最佳位所在侧；先比较实际浪潮风险，再比较炮群相对位置给出的南北侧偏好、侧向偏移、距基地与墙血量。无法安排全部 `count` 个合法点时返回 `None`，不拆成多个墙目标。

不新增官方请求字段，`roleCommandMap` 继续以实际机器人 ID 发单个 `move` 或 `attack`；原生机器人攻击不带炮台 `controllerId`。所有指令经过 `ActionPlan.add()`，射程、地图边界和数量校验不因策略优先级放宽。

## 浪潮风险与验证边界

用户希望不同侧出生同时避开敌方浪潮。规划结合地图外侧方向、基地位置和当前实际机器人分布择优；不把“左上 / 右下”当成完整官方浪潮出生或选敌算法。官方 §4.7 没有完整规定出生采样和路线，因此本版实现的是风险偏好，不能保证不会与浪潮相遇。实际旁移、被阻挡或被攻击仍依反馈处理。

本轮仅验证第一天：保护 / 非保护阵型、两张示意与镜像、45°无墙遮挡、单至三 BOSS 合法出生、共同墙目标、真实破口、占位后全队基地集火、当前移动单位视野及失败反馈。准确检查数量、HTTP 场景、源码哈希和未覆盖范围由 [VALIDATION-v1.2.21](../../reports/VALIDATION-v1.2.21.md) 记录。这些是本地策略与接口证据，不代表新版官方对局成绩。

后续修改先检查 `wall_assault` 共享计划、每只 BOSS 的真实位置 / 指令 / 上轮动作结果，以及 `robot_diagnostic` 的保护判定、共同墙、基地射线和最终决策。区分“规划可达”和“平台实际成功”；不要从动作被接受直接推断墙已拆掉或敌人已死亡。
