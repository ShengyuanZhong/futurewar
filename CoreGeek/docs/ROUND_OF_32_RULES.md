## 已确认的关键变化及未来代码入口

| 主题 | 复赛 v2.0 要求 | 当前接入状态与未来位置 |
|---|---|---|

| 破坏与抓捕 | `destroy` 连续4回合破坏邻格矿，任一回合中断清零；`catch` 可由任何角色抓邻格敌方捣乱鬼，成功得20金币 | v1.1.0接入destroy字段/权限校验和昼夜连续策略；catch尚未接入，后续需避免把抓捕收入误判为任务奖励。详见[捣乱鬼策略](IMP_STRATEGY.md) |
| 矿区半区与余量 | 两半区矿石刷新数相同；被破坏的该半区该类矿10回合不补刷；Zone 新增 `remain` | `protocol.py` 当前仅存坐标→类型，未保留 `remain`；采矿选择可在后续读取余量与破坏状态 |
| 可驾驶小车 | 完成任务点2获得，白天存在；进入己方车辆格即驾驶，`isDriving` 指示状态，驾驶移动可走2格；敌车格不可进入/建造 | `protocol.py` 未保留 `isDriving` 和车辆归属；`grid.py`/`actions.py` 仅按步行单格移动，`brain.py` 未规划车辆。任务点2完成反馈与车辆出现可能跨日 |
| 可控机器人 | 召唤令改为召唤己方机器人，使用时必须给合法目标坐标；夜间首回合生成，`teamOur.summonRobotList` 标识己方机器人，可在 `roleCommandMap` 以其 ID 发 `move/attack`，无命令原地待命 | `protocol.py` 尚未解析己方归属列表，`actions.py` 沿用旧召唤令语义且未校验目标，`brain.py` 不调度可控机器人。`robot.roles` 包含双方/系统机器人，不能仅靠该列表推断归属 |
| 伤害与价格 | 加特林每颗25；电磁能量 L1/L2/L3 为20/40/60。WallFixer 15，DizzyWeapon/Bomb 50，任务用品10，召唤令15/20/70/120 | `brain.py` 的伤害估值与升级/补货预算、`config.py` 的兜底价格及文档需核对。采购应优先读每回合 `weaponShopList` 实价；不能沿用旧召唤令用途 |
| 命令反馈与错误 | `lastCmdResult` 第二行固定 `[durationMs:N]`；`errors` 增加网络错误码3，指令错误码4；动作反馈 key 可是角色或可控机器人 ID | `protocol.py` 的命令结果解析、`task_evidence.py` 的输出提取与日志、`task_service.py` 的错误分类需按新版报文验证。现有任务控制器只处理部分错误码 |
| 计分边界 | 比赛提前结束时，生存积分只计至实际结束日 | 选手程序不自行结算胜负；评估脚本及开发文档不得把未到达天数算入官方成绩 |

新版[request.txt](../../32_docs/request.txt)在v1.1.0能输出新增imp的合法移动动作；车辆、己方机器人等新增字段仍不参与完整决策，这**不等于全部复赛功能已兼容**。后续分别增加协议、动作、策略和官方回放验证，保留v1.0基线。

## 待核对的文字歧义

- v2.0任务书 §4.5.4 的驾驶碰撞描述称“第2格受到碰撞”同时又称“整体停留在第2格”。实现两格移动结算前应以官方说明或真实回放核对预期位置，不自行改写原文。
- v2.0任务书 §八开头列“四类”异常，末尾注释仍写“上述三类”。实现时按列出的类别与接口错误码处理，若判题口径不同需另记证据。
- v2.0接口 §2.2 对 `attack` 通用 `controllerId` 的说明主要针对武器；可控机器人 `attack` 的 `controllerId` 要求未在正文单独说明。发送机器人攻击前需以官方示例和反馈验证字段形状。
