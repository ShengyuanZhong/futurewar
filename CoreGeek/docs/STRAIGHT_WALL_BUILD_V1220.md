# v1.2.20 首日直墙连续施工

本版根据 `temp/build_bug3.log` 修正首日建墙时的隔格施工、回补和外侧 Z 字行走。工人按自己的稳定施工段，依次完成实际尚未建成的墙；直墙优先沿正对墙面的外侧轨道走，完成个人施工段后立即进入采购或侦察任务。采购工的购物截止继续高于未完成施工，不要求等待整圈墙齐。

这是团队策略优化，参照 [v2.0任务书](../../32_docs/任务书.md) §4.1、§4.4、§4.5.4 和 [v2.0接口文档](../../32_docs/接口文档.md) §2。工人只能白天建墙，每轮一个目标，目标距工人一格且背包有石头；距离仍采用切比雪夫距离，正常寻路仍允许八方向移动。这里的直线施工偏好不改变官方移动、碰撞或建造范围。官方资料与用户原始日志均保留，正式程序不依赖 `temp/`。

## 当前施工流程

1. 根据实际基地、商店、敌基地与工人身份保留稳定的两段墙分工。个人石头配额、矿区真实余量和联合分矿沿用 v1.2.17。
2. 每轮先读取实际缺墙，再按个人弧顺序选第一个合法可达的缺墙。取消旧 `LOCAL_DETOUR` 距离插入规则；旧途中 `build:wall` 目标不能越过当前首个实际缺墙。仍在采矿的同伴不被视为已经放弃自己的施工段。
3. 为目标墙选择外侧施工站位。直墙优先选择正对外法线的一格；角点依据下一段方向，段尾依据上一段方向选择站位。站位必须处于完整封闭蓝图的外侧，避开实际障碍、未来墙/炮、同伴目标和本轮预约。
4. 工人当前位置与外侧施工站位同轴、整段外侧轨道空闲时，沿该轴前进。步行输出一格；只有当前真实 `isDriving` 且白天才可输出最多两个连续邻格。转角、远处接近或真实障碍绕行继续用原八方向路线。
5. 工人必须实际到达选定施工站位才发 `build`。不能仅因处于目标的任意斜邻格就提前建墙，使站位与施工顺序保持一致。实际石头、日间权限、日照预算及防止困住工人的封闭安全检查仍需满足。
6. 当前敌方占位、站位真实不可达或封口安全不允许的墙可以暂时跳过，继续其它可执行施工，不凭空预测敌人离开。携石工人仍有个人施工未完成、暂时无可执行建墙动作时记 `build_wait`，不转去普通收入采矿。
7. 最后一条 `build` 提交后，必须等下一轮观测确认墙真正存在，才满足个人完工交接。个人段实际完成后采购工立即赴店，侦察工立即探路；不等待同伴墙段完成。购物出发截止仍可能提前释放采购工，随后由其它在场施工者接管遗留墙。

## 模块、函数与参数

| 文件 / 函数 | 参数与返回 | 作用与维护要点 |
|---|---|---|
| [wall_schedule.py](../src/agent/wall_schedule.py) `WallSchedule.targets(role, candidates, local_only=False)` | 当前工人、合法候选墙集合、是否仅就地施工 → `list[Pos]` | 按个人弧顺序返回实际缺墙；过滤不可达目标。`local_only=True` 只返回当前已在其选定站位的首墙，不能另挑斜邻墙。 |
| 同上 `posts(role, target)` | 当前工人、墙坐标 → `set[Pos]` | 直边法线站位和角点方向；不可用时从真实合法站位回退，缓存键包含本轮预约及同伴目标。 |
| 同上 `straight_steps(role, goal)` | 当前工人、已选站位 → `tuple[Pos, ...]` | 整条同轴外轨空闲才返回轴向步数；步行最多 1 格，真实驾驶最多 2 格。返回空元组时保留通常路线。 |
| 同上 `cost(role, target)` | 当前工人、墙坐标 → 路径轮数或不可达值 | 用真实外侧路线及同一 `posts` 计算；供可达性与日照预算检查，不用于插入隔格目标。 |
| 同上 `assigned_missing/remaining/construction_ready/release` | 当前工人及可选交接使命 | 真实个人缺墙、材料配额和完工交接；提交命令不会减少实际缺墙。 |
| [brain.py](../src/agent/brain.py) `Strategy.build_wall(role, local_only=False)` | 当前工人、是否仅就地施工 → `bool` | 按调度目标走到 `posts` 后实际建造；继续检查真实石头、出口安全、当轮其它施工及日照。 |
| 同上 `opening_worker(role)` | 当前工人 → `bool` | 首日施工阶段的筹石、建墙与暂时 `build_wait`；个人下一使命由原有采购/侦察优先分支接管。 |
| [stone_planner.py](../src/agent/stone_planner.py) `StonePlanner.can_build_now(role)` | 当前工人 → `bool` | 与建墙使用同一首缺墙、选定站位和安全条件，避免采矿预判与施工输出不同步。 |
| [worker_coordinator.py](../src/agent/worker_coordinator.py) `WorkerCoordinator.move_to(role, goals, kind='travel', target=None, allowed=None, allow_risk=False, route=None)` | 角色、目标集合、任务类型、业务目标、允许区域、夜间风险许可、可选真实路线 → `bool` | `build:wall` 路径使用空闲外轨轴向步；其余旅程继续原寻路、车辆及协作让行。 |

不新增用户配置项或官方报文字段。`WallSchedule` 只在首日日间且完整蓝图可用时启用；后续昼夜经济、维修、炮台索敌、任务模块和三火箭 BOSS 策略保持现有实现。

## 诊断和验证

| 日志字段 | 查看内容 |
|---|---|
| `wall_schedule.arcs/frontier/remaining/released` | 个人段顺序、当前首缺墙、真实剩余数量与交接记录 |
| `worker_motion.position/target/goal/command/last_action_ok` | 真实工人位置、业务墙目标、外侧施工站位、实际输出动作和上一轮平台反馈 |
| `worker_jobs` 中的 `build:wall/build_wait` | 正在施工或携石暂时等待；`build_wait` 不代表已完工 |
| `home_construction.missing/inside_workers/physical_closed` | 真实缺墙、工人是否仍在内部、完整闭合是否实际完成 |
| `stone_mining`、`stone_quota` | 矿点余量、采集预约和个人材料需求，不能把配额当作已入背包 |
| `first_day_policy/raid_survey` | 个人完工后赴店/侦察的真实派发轮次，以及采购截止和阵型视野状态 |

排查应将本轮指令与下一轮实际建筑、位置和反馈对应检查；`target` 或 `goal` 不是工人的真实位置。只看到斜向 `move` 不能认定建墙失败，缺墙也需区分尚未施工、占位暂跳、封口安全暂缓和平台明确失败。

本轮验证仅覆盖第一天，包含顺序补缺、直轨移动、镜像、角点、实际占位/车辆、封闭安全和个人交接。完整检查结果、源码哈希及连续 HTTP 范围见 [VALIDATION-v1.2.20](../../reports/VALIDATION-v1.2.20.md)；本地检查不等同新版官方对局。旧两步绕行策略的历史设计见 [v1.2.16](WALL_SCHEDULE_V1216.md)，个人分矿与交接见 [v1.2.17](FIRST_DAY_MINING_V1217.md)。
