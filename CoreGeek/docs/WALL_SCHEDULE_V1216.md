# v1.2.16 首日建墙调度与个人材料分工

2026-10-13。本版根据用户的 `temp/build_bug.log`（请求中称为 `builg_bug`）调整建墙调度：两名工人的首日后续目的分别是实际商店与敌方基地，因此施工应尽量在离开方向的一侧结束。计划中的17块墙、三座火箭及操炮位不变，工人仍先实际撤出未来封闭区域、随后从外侧建墙。

这属于团队策略调整。建造权限、材料、距离与占用继续依据 [v2.0任务书](../../32_docs/任务书.md)和[接口文档](../../32_docs/接口文档.md)；原文及用户日志保留，不通过改写资料迁就测试。正式程序不依赖 `temp/`。本轮验证仅覆盖首日，本地证据、数量和源码哈希见[验证报告](../../reports/VALIDATION-v1.2.16.md)，没有新版官方对局验证。

## 日志中的实际问题

该局己方基地左上角为 `(30,10)`，敌基地为 `(9,22)`；采购路线中的合法商店交互站位为 `(24,19)`。日志未直接记录商店本体坐标，不能把推算的 `(24,20)` 写成已确认的官方观测。验证中若使用这个商店本体坐标，属于明确的本地输入假设。

问题并非简单的全部墙自上向下施工，而是未协调后续方向、历史缺口抢单与墙材分配：

| 回合 | 观测与动作 | 影响 |
|---|---|---|
| R31～R36 | 从南侧、右侧开始施工 | 这段与之后向北离家的方向并不冲突 |
| R37～R46 | 采购工在南侧 `(32,6)`，被历史占点修补分支派往 `(28,11)` | 远程修补抢占普通建墙安排，造成一段绕行 |
| R47 | 另一工人在北侧 `(30,13)` 用完8块石头；采购工仍有7块 | 团队总库存掩盖了个人施工区缺材，前者转去采铜 |
| R49、R50、R52 | 采购工又回到西南段建墙 | 刚到北侧后再次向南回返，结束位置离后续任务更远 |
| R54 | 采购截止到来，采购工携4块石头离家；另一工人再从 `(36,12)` 返回南矿 `(36,4)` | 购手离开后才重新筹缺石，反向行程进一步消耗日照 |
| R70 | 首日仅确认13墙，仍缺4墙 | 筑墙与购物都被前面的调度浪费挤压 |

该局第三次任务到 R65 才结束，采购工当时还剩赴店行程；这也是购用未完成的时间因素。新施工规划减少此前的行程浪费，继续保留购物截止优先，但不声称能保证任何任意延后的任务结算都可在日落前完成三张券。

旧 `Strategy.build_wall()` 按有效旧目标、最近交互距离、坐标排序，没有后续商店和侦察目的。计算目标距离时又包含最终不能采用的内侧交互格，使估算距离与外侧实际施工路线不一致。首日日间的 `WallGapDefense.worker()` 则在普通施工之前追逐已腾空的历史缺口，使局部抢单进一步破坏路线。

## 施工方向与稳定分工

实现位置：[src/agent/wall_schedule.py](../src/agent/wall_schedule.py)。`WallSchedule`只在第一天白天、存在有效基地和封闭计划时启用，负责选择目标，不改变 `SealedHome` 与 `ActionPlan` 的安全和权限校验。其它天仍保留原补建及维护流程。

1. 从真实 `weaponShop` 中取得采购工目的；从实际敌方基地观测取得另一工目的。缺少资料时只用地图中央作规划回退，不把推算镜像商店当成可交易对象。
2. 以2×2基地中心为参考，把两名工人的后续目的方向组合，确定较合适的离开侧。墙位按相对基地的圆周顺序排列，划为两段，各段从较远侧向离开侧推进。基地在左上时可以向南或东南收尾，基地在右下时可以向北或西北收尾，取决于真实目的坐标。
3. 比较两种工人与施工段的配对，兼顾开始施工的实际可达成本、段内行程及结束后到个人目的的距离。如果首次规划时两名工人已经携石、总量足以完成缺墙，则比较切分点，优先让各段适配真实背包，再比较路线成本；例如日志中的9/8库存不必为新的7/10分段额外回矿。分配完成后保存在跨回合记忆中，墙的实际完成与一次移动不会导致每轮交换分工。
4. 每轮仍按真实占用、同伴预约与外侧通行更新可行目标。对手暂时占住某墙不会冻结整段；同伴死亡、已承担采购或侦察使命、或无石头无法立即施工时，允许另一人接手可施工的墙。

分工是稳定偏好，而非禁止协作的硬边界。单人可继续补完整个计划，不要求空闲工人站着等待自己的段重新出现。

## 下一墙与外侧站位

目标比较使用最终合法的外侧施工格：目标八邻格中，排除计划墙、炮位、同伴交互站位及本轮真实预约，再由 `SealedHome.builder_posts()`保留外侧格。路线距离据此计算，不能先按内侧格报一条短路，实际执行时再改走外圈。

`LOCAL_DETOUR = 2`表示相对当前最近合法候选墙，按段推进的下一墙至多增加两步路程。仍在此范围内时优先保留规划方向；更大的绕行则允许插入附近可施工的墙。这个值是策略参数，不是游戏规则，也不是预留回家时间。

有效的途中 `build:wall` 目标继续完成，条件包括近期真实任务记录、目标仍可施工和未连续停滞。目标建成、被占、不可达或持续停滞时重新选择。不因每一回合出现更近的墙而中途掉头，也不强行保留失效预约。

`local_only=True`只检查同一规划下一墙是否恰好与工人相邻，不能再次独立挑另一堵相邻墙绕过施工方向。`StonePlanner.can_build_now()`与 `Strategy.build_wall()`使用同一排序来源，避免“探测可以就地造、执行却选另一目标”的分歧。

安全边界沿用[永久封闭建家](SEALED_HOME_V1215.md)：

- 工人在下一次观测确认位于外侧之前，不以移动指令预测其已经撤出。
- 三炮真实完成后，首日日间已经在外侧的工人，普通施工、采矿、让行和侦察路径都限制在外侧；不能走过未建内圈再被撤出分支拉回。初始炮台施工不采用这个限制。已经开始的 `construction_exit` 先走到真实外侧，不能在未建边界格切回采石而反复进出。
- 施工同时考虑本轮所有已接受的建墙预约，防止两堵墙共同封住真实内部工人。
- 首日购物截止仍可中断施工，且不预留回家预算；保留夜间禁建、八方向移动、车辆站位与同时占用约束。
- 计划墙不会为了通行被自动拆除，也不恢复临时入口或额外围挡。

## 按个人剩余施工筹石

实现位置：[src/agent/stone_planner.py](../src/agent/stone_planner.py)。`StonePlanner.targets()`继续只统计真正缺墙、实际背包与可参与施工的工人。首日优先参考 `WallSchedule.remaining(role)`分配墙材，再考虑容量、已有库存、有效采石份额和其它真实缺口。

两段可能有7墙与10墙，因此不再固定按9与8块石头分份。尚未采齐时，每人的目标尽量覆盖自己实际未完成的段，减少“自己的石头先用完、同伴携余石绕去另一侧”的情况。现有石头仍优先利用，不因规划变化额外采17块；个人分工也不能把团队真实剩余缺口重复累加。

采购或侦察工人实际离开施工使命后，不再将它携带的石头视为在家施工工人的材料；留家工人可接手剩余段及筹材。只提交建造、采集或移动指令不会提前改变建筑、背包或真实缺墙数，下一轮观测才确认结果。

石矿选择继续先利用当前邻近合法矿点，否则保留有效行程；两个工人可采同一矿但使用不同站位。矿消失、失败冷却、停矿新闻或实际路线失效时换目标。普通铁铜采矿、售矿、批量购券、修包与夜间维修流程仍保留。

## 历史占点与夜间接力

实现位置：[src/agent/gap_defense.py](../src/agent/gap_defense.py)。首日白天对手离开预建位后，该位置仍是缺墙，但远程修补交回普通建墙调度，不强迫特定采购工先绕过去。如果携石工人已在相邻合法外侧格，可立即补建并继续检查封闭安全。

首夜真实空缺口由工人肉身补位、捣乱鬼待命或接替的策略保留。工人尚未实际返抵时仍按真实位置交接，不把预期移动或预期死亡当作当前事实。此次没有恢复额外城墙包围占点单位的旧策略。

## 关键函数与状态

| 函数 | 参数与返回 | 用途 |
|---|---|---|
| `WallSchedule(strategy)` | 当前 `Strategy` | 绑定本轮观测、施工安全和跨回合分段状态 |
| `Strategy.worker_region(role,allowed=None)` | 角色、可选通行集合 → 集合或 `None` | 首日三炮完成后，外侧工人的默认路线保持在外侧；显式限制仍沿用传入集合 |
| `destinations(workers)` | 存活工人列表 → `dict[int,Pos]` | 采购工读取真实商店，另一工读取敌方基地；未知资料采用规划回退 |
| `prepare()` | 无 | 按当前蓝图生成稳定施工两段并比较工人配对；已有同蓝图分段保持 |
| `active_builders()` | 无 → 工人列表 | 排除正在执行采购或侦察使命的角色 |
| `posts(role,target)` | 工人与墙坐标 → `set[Pos]` | 与真实执行一致的外侧合法交互站位 |
| `cost(role,target)` | 工人与墙坐标 → `int` | 到合法外侧站位的路径步数；不可达返回10000 |
| `targets(role,candidates,local_only=False)` | 工人、合法候选墙、仅就地标记 → `list[Pos]` | 下一墙及回退顺序；考虑个人段、两步额外路程与有效途中预约 |
| `remaining(role)` | 工人 → `int` | 个人真实未完成施工需求，允许接手失去施工者的墙 |
| `diagnostic()` | 无 → `dict` | 蓝图、目的、分段、下一墙及个人剩余需求 |

`GameMemory.sealed_home['wall_schedule']`保存规划，沿用现有记忆对象，不新增官方请求字段。主要字段如下：

| 字段 | 内容 |
|---|---|
| `blueprint` | 本次真实配置墙位，用于识别布局变更 |
| `destinations` | 每名工人的后续目的坐标 |
| `departure` | 规划离开侧的参考墙位，不表示工人已抵达 |
| `arcs` | 工人ID对应的有序墙位列表 |
| `assigned_round` | 本次分段确定回合 |
| `frontier` | 当前每工选出的下一墙 |
| `remaining` | 诊断时计算的个人未完成施工需求 |

已有 `worker_tasks`继续记录 `kind/target/goal/moving/stalled/stone_quota`。`kind`描述真实角色当轮使命；分段中的墙位不等于永久占用预约，不能把整个未建墙环标成不可通行。排查折返时同时核对这两类数据、实际位置、真实背包及上一轮动作反馈。

## 本地验证与后续修改

首日回归覆盖两种基地方向、固定非镜像商店、真实外侧站位、有效途中任务、采石配额、对手占点腾空、购物截止和同时封墙安全；连续HTTP场景的具体输入假设与结果列在[本版验证报告](../../reports/VALIDATION-v1.2.16.md)。这些是本地规则和流程检查，不是官方对局复现或胜率。

另提供 [compare_wall_schedule.py](../tools/compare_wall_schedule.py)，在同一组首日公开输入中比较 `6283eb8` 的旧施工策略与当前策略。右下局部场景封墙从R55提前到R50，施工移动加后续行程估算从52步降为47步；左上场景封墙从R54提前到R52，但该步数指标从50增至53。此分段优先保持方向和并行施工，不保证所有地图的总路程都最短。比较从三炮已建、工人已有9/8石头开始，没有复现整场官方对局。

修改施工方向、两段配对和额外路程范围从 `WallSchedule.prepare/targets`开始；修改材料份额从 `StonePlanner.targets`开始；修改防困工人从 `SealedHome.safe_wall/evacuate`开始。购物截止、先锋2→1→2任务、当前共享视野与[多BOSS进位](BOSS_FORMATION_V1214.md)不在本次调参范围内。
